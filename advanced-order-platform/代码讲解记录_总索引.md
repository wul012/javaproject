# Java code walkthrough archive index

This file is the navigation entry for Java code walkthrough documents. Evidence archives under `a/`, `b/`, `c/`, `d/`, and `e/` remain versioned evidence; this index is only for human code walkthroughs.

## Active rule

Walkthroughs are optional for a version, but any committed walkthrough must follow `代码讲解记录_写作规范.md`.

Do not keep adding hundreds of files to one directory. When a walkthrough directory grows beyond roughly 60 files, continue in a new sibling folder or split the active folder by version range.

Historical files marked `legacy-nonstandard-walkthrough` are preserved for traceability only. They are not standard walkthroughs until rewritten under the current writing standard.

From Java v1774 onward, committed version walkthroughs are Chinese longform documents. Each version walkthrough must contain at least 3000 Chinese characters, include `## 实际工作量说明`, avoid padding, and remain grounded in this project's route, model, service, evidence, boundary, and test details.

## Evidence summary folders

Folders like `e/<version>/解释/` are evidence summaries, not the primary code walkthrough archive. They may summarize a receipt, screenshot, or generated artifact, but a code walkthrough belongs in a `代码讲解记录*` folder and must use the required walkthrough structure.

Runtime screenshot/explanation artifacts should not keep accumulating in the historical `d/` root or the v1759-v1763 transition root. New screenshot and explanation archives continue under range-segmented folders such as `f/v1769-v1773/`, with `images/` and `explanations/` separated per version.

## Batch cleanup policy

- Batch 1: split `代码讲解记录_生产雏形阶段3` into version bands and make archive tests recursive.
- Batch 2: revise or replace short receipt-style walkthroughs when those versions are touched again.
- Batch 3: if earlier historical folders become hard to navigate, split them with the same range pattern and keep a root README as the entry point.
