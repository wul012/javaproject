# Java v240 v1 contract consumer readiness handoff legacy registry alignment

v240 把上一轮 full test alignment 正式版本化。

这版的核心是区分两条 registry：
- `OpsShardReadinessV1ContractEndpointPairs` 是 v1 consumer 合同 registry，必须保持 11 个 pair，并且以 readiness handoff 作为最后一个 consumer pair；
- `OpsShardReadinessEvidenceEndpoints` 是更宽的滚动证据 registry，可以继续包含 read-only catalog 和后续 runtime closeout 条目。

如果这两条 registry 混在一起，旧的 bundle/checklist 测试就会把 read-only catalog 当成 v1 consumer 合同的一部分，导致 frozen contract 的语义被扩大。
v240 用独立测试确认：
- live endpoint registry 没有重复；
- fixture endpoint registry 没有重复；
- consumer endpoint catalog -> bundle -> checklist -> digest -> readiness handoff 顺序不变；
- read-only catalog 与 runtime execution closeout 不进入 frozen v1 consumer registry；
- rolling evidence endpoints 仍然保持 echo -> v1 alignment -> evidence digest -> readiness handoff -> read-only catalog 的顺序。

因此，v240 的意义是把“全量测试已对齐”的事实沉淀成可追踪证据，而不是只停留在一个补丁提交里。
