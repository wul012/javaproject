# Java v183 v179 verification snapshot freeze

本版修正一个后续扩展风险：v179 的 catalog handoff verification 之前读取滚动全局 registry。只要后续再新增 endpoint，v179 运行态响应就会从 22/22 变成新数量，和 v179 静态 fixture / 证据归档不再一致。

## 变更

- 新增 `OpsShardReadinessReadOnlyEvidenceCatalogHandoffVerificationSnapshot`。
- v179 verification service 改读 v179 固定 22 live / 22 fixture snapshot。
- 新增 `OpsShardReadinessReadOnlyEvidenceCatalogHandoffVerificationSnapshotTests`，锁住 v179 snapshot 数量和关键 read-only catalog endpoint。

## 边界

- 没有新增 HTTP endpoint。
- 没有改变 v179 response 字段名、路径或 status。
- 未新增 write routing、active shard router、credential value、raw endpoint parse、managed audit connection、deployment / rollback。
- Node 仍不得自动启动或停止 Java / mini-kv。

## 验证

- focused: `mvn -q "-Dtest=OpsShardReadinessReadOnlyEvidenceCatalogHandoffVerificationSnapshotTests,OpsShardReadinessReadOnlyEvidenceCatalogHandoffVerificationServiceTests,OpsShardReadinessReadOnlyEvidenceCatalogHandoffVerificationIntegrationTests,OpsShardReadinessEvidenceEndpointsTests" test`
- full: `mvn -q test`
