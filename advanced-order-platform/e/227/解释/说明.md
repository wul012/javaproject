# Java v227 v225 consumer readiness handoff historical compatibility

v227 验证 v225 readiness handoff 的历史兼容性。

这里的关键不是“当前能不能访问新 endpoint”，而是确认新 endpoint 只属于当前滚动 registry，不会悄悄回填到
早期已经冻结的 snapshot 中。早期 snapshot 是历史证据，如果后来版本把新 endpoint 塞进去，就会破坏“当时发布时看到的世界”。

本版新增 `OpsShardReadinessV1ContractConsumerReadinessHandoffHistoricalCompatibilityTests`，覆盖三条线：

- v179 read-only handoff verification snapshot 不包含 v225 readiness handoff；
- v184 read-only endpoint registry integrity snapshot 不包含 v225 readiness handoff；
- 当前 rolling evidence registry 中，Java v220 digest、Java v225 readiness handoff、read-only catalog 保持顺序；
- frozen v225 handoff 不吸收 v226 snapshot freeze 和 v227 historical compatibility 证据。

这让后续继续加 v228、v229 等 guard 时，可以明确区分“新版本证据归档”和“v225 handoff 原始合同”。
