# Java v155 说明：shard readiness frozen evidence index

本版继续 Java shard readiness hardening。Node v376 已消费 Java v154 和 v153 source core，本版把已完成 Java 证据整理为冻结索引，供后续 Node 版本按版本化路径消费。

## 输出

- Live endpoint: `GET /api/v1/ops/shard-readiness/evidence-index`
- Static fixture: `GET /contracts/java-shard-readiness-evidence-index-v155.fixture.json`
- Archive evidence: `e/155/evidence/java-shard-readiness-evidence-index-v155.json`

## 本版新增

- `Java v153`：核心 shard readiness 十字段来源。
- `Java v154`：hardening 字段解释和失败语义来源。
- 每个来源都明确 versioned endpoint、versioned fixture、archive path。
- `rollingCurrentPointer=false`，禁止后续消费者把历史基线指向滚动 current 文件。

## 结构拆分

本版新增 `OpsShardReadinessController`，把 `shard-readiness`、`shard-readiness/hardening`、`shard-readiness/evidence-index` 从 `OpsOverviewController` 中分离，避免 overview controller 随 shard 证据继续膨胀。

## 边界

- 不修改 Java v153 / v154 输出。
- 不修改 Node v370-v376 归档。
- 不启用真实 shard 路由。
- 不改订单、支付、库存、ledger 或 SQL。
