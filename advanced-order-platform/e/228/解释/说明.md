# Java v228 v1 contract consumer readiness handoff integrity

v228 给 v225 readiness handoff 增加完整性护栏。

这个测试不是只看 endpoint 能不能返回，而是把 handoff 的核心合同拆成几组精确断言：

- `digestEvidence` 必须等于 frozen Java v220 digest 的证据列表；
- `handoffGuardEvidence` 必须等于 v221-v224 四条 digest guard 证据；
- `handoffChecks` 必须保留 digest version、digest count、guard count、GET-only、upstream denied 和 no-process-control 检查；
- v226、v227、v228 这些后续 handoff guard receipt 不能进入 frozen v225 handoff；
- 所有执行边界字段继续保持关闭。

这样后续版本可以继续增加证据、fixture、文档和消费者校验，但不会悄悄改变 v225 handoff 的原始语义。
