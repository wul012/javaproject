# Java v160 说明：operator service lifecycle evidence

Node v385 已验证 Node v384 对 Java v159 与 mini-kv v150 live-read gate plan 的归档回放。Node 下一步等待 operator-owned service lifecycle evidence。Java v160 补上 Java 侧只读 lifecycle evidence：声明 owner、启动/停止责任、端口/baseUrl 模板、GET-only smoke、fail-closed 与 cleanup 责任，但不启动服务、不打开 runtime probe。

- Live endpoint: `GET /api/v1/ops/shard-readiness/operator-service-lifecycle`
- Static fixture: `GET /contracts/java-shard-readiness-operator-service-lifecycle-v160.fixture.json`
- Archive evidence: `e/160/evidence/java-shard-readiness-operator-service-lifecycle-v160.json`

- `lastVerifiedByNodeVersion=Node v385`

## operator lifecycle 边界

- Java service owner / start owner / stop owner 均是 operator confirmation 范畴。
- Java port 或 baseUrl 必须在 live-read window 前由 operator 明确声明。
- Node 只可消费本冻结证据，不能从本证据启动或停止 Java。
- smoke targets 必须保持 GET-only。
- owner、port、cleanup 或 smoke 任一缺失都 fail closed。

## 边界

- 不修改 Java v153-v159 输出。
- 不启动或停止 Java / mini-kv。
- 不执行 runtime probe。
- 不读取 credential value 或 raw endpoint value。
- 不启用 active shard router、write routing、多进程分片或写命令。
