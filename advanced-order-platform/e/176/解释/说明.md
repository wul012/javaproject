# Java v176 catalog snapshot freeze

This version hardens the Java v175 read-only evidence catalog.

## What Changed

- Added `OpsShardReadinessReadOnlyEvidenceCatalogSnapshot`.
- Moved the v175 catalog endpoint lists into a frozen snapshot.
- Updated `OpsShardReadinessReadOnlyEvidenceCatalogService` to read the frozen v175 snapshot.
- Added a snapshot test that locks the v175 endpoint order and counts.
- Added v176 evidence JSON and HTML archive files.

## Why

The v175 catalog is versioned evidence. If a later version adds more shard-readiness endpoints, v175 must keep returning the v175 endpoint set instead of drifting with the global registry.

## Boundaries Held

- No root readiness schema change.
- No write routing.
- No active shard router.
- No credential or raw endpoint reads.
- No managed audit connection.
- No Java or mini-kv process start/stop.
- No deployment or rollback path.
