# Java v156 说明：shard readiness evidence verification

本版继续 Java shard readiness hardening。Node v376 已消费 Java v154/v153，Java v155 已建立冻结证据索引；v156 在 Java 侧补一层验证回执，确认这些冻结来源不依赖 rolling current。

## 输出

- Live endpoint: `GET /api/v1/ops/shard-readiness/evidence-verification`
- Static fixture: `GET /contracts/java-shard-readiness-evidence-verification-v156.fixture.json`
- Archive evidence: `e/156/evidence/java-shard-readiness-evidence-verification-v156.json`

## 本版验证

- v155 index 仍是 `readOnly=true`、`executionAllowed=false`。
- Node regular-gate 九个字段仍被覆盖。
- 冻结来源仍是 Java v153 core + Java v154 hardening。
- 所有来源 `frozen=true`。
- 所有来源 `rollingCurrentPointer=false`。
- fixture endpoint 和 archive path 都是显式版本化路径。
- Java 不回写 Node v370-v376 归档链。

## 结构优化

新增 `OpsShardReadinessEvidenceEndpoints`，集中维护 shard readiness live endpoint、fixture endpoint 和 GET probe 形式。`OpsEvidenceService` 以后只调用这个 helper，不再每一版重复硬编码同一组 endpoint。

## 边界

- 不修改 Java v153 / v154 / v155 输出。
- 不修改 Node v370-v376 归档。
- 不启用真实 shard 路由。
- 不改订单、支付、库存、ledger 或 SQL。
