# Java v241 v1 contract consumer readiness handoff post-handoff catalog

v241 做的是一次必要拆分。
v226-v240 已经积累了很多围绕 v225 readiness handoff 的验证 receipt，如果继续在每个测试里手写路径清单，后面很容易漏加、重复、或把版本顺序写错。

本版新增 `OpsShardReadinessV1ContractConsumerReadinessHandoffPostHandoffEvidenceCatalog`。
它用一个小 record 表达三件事：
- Java version；
- 该 receipt 的 scope；
- evidence path。

这样后续测试不需要再复制一长串常量，而是直接读取 catalog。
v241 的测试确认：
- catalog 覆盖 v226-v241；
- receipt 数量是 16；
- v240 legacy registry alignment 和 v241 post-handoff catalog 都已纳入；
- catalog 中的 evidence path 不会回填到 frozen v225 `digestEvidence`；
- catalog 中的 evidence path 不会回填到 frozen v225 `handoffGuardEvidence`。

这版的价值不是扩大功能面，而是把后续 18 版的验证基础打稳。
