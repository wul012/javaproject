# version-1846：Operator-CI 消费包层拆分讲解

本篇解释 Java 本项目 v1846 的实际机制。v1845 已把归档验证压成结构化摘要，但摘要仍偏向“系统内部汇总”；v1846 继续把摘要整理成不同角色能接收、能复核、能按顺序处理的 ConsumerPackage。它不下载文件、不启动命令、不发布消息，而是生成 manifest、受众、章节、验收条件、CI 矩阵、边界锁、交接清单、分数卡和可读 Markdown。以下内容遵守“禁止硬凑”，每一处数字和流程都对应现有源码或机械门。

## 实际工作量说明

这一版迁移二十三个生产类和四个包内测试。生产类覆盖来源摘要投影、五项 manifest、四类消费受众、五个包章节、五条验收标准、五项 CI 矩阵、八个边界锁、五项交接清单、八项分数卡、九个 Markdown 章节及其渲染器、服务、响应和构造支持。它们共同回答一个问题：一份已经通过归档摘要的证据，怎样被组织成 operator、CI 和 release-review 都能消费的只读交接包。

控制器继续留在根 `ops` 包，控制器 Markdown 聚合测试也继续留根。控制器是公开 HTTP 地图的一部分；该测试既核对入口又核对整份 Markdown 聚合结果，保留在入口层更清楚。边界清单、目录、来源和测试工厂共四个测试随包移动。新包只公开 service、不可变 response 和一个测试工厂，二十余个目录与渲染器仍是包内实现，没有扩大公共 API。

根目录文件由六百二十一降至五百九十八，可迁移非控制器由五百一十六降至四百九十三，Operator-CI 桶由九十六降至七十三，未归类为零。总 `ops` Java 文件没有增加，继续受一千三百五十二上限约束。v1846 不是把一个大类拆成许多更小但无意义的空壳，而是把已经存在、已经有测试的一组完整责任迁到合适包中。

## 路径决策与偏差记录

按类名前缀直译，最自然的包名会是 `minimalreadonlygateoperatorcihandoffarchivedigestconsumerpackage`。在实际移动前测量目标路径，最长文件会达到二百六十四字符。这个数超过传统 Windows 路径边界，并且本仓库此前已经发生过深包路径导致迁移中断的事件。若仍坚持完整前缀，工程风险不是理论上的“可能”，而是可复现的文件系统失败。

因此本版选择 `minimalreadonlygateoperatorciconsumerpackage`。它保留四个关键信息：最小只读闸门、Operator-CI、消费包、维护实现；省去已经由上游 import 表达的 handoff/archive/digest 祖先链。新包最长路径实测二百四十四字符，比完整方案减少二十字符。类名、端点、响应字段、JSON 形状、配置档和历史归档均不改变，只有 Java 包所有权变短。

这一偏差不是悄悄绕开规范。证据页记录二百六十四和二百四十四两个测量值，v1846 治理测试要求短包出现并拒绝过长包段，终局 census 也写入选择理由。这样以后维护者能区分“为了偷懒缩写”和“为了跨平台可操作性保留语义的短包”。

## 入口路由

ConsumerPackage 端点仍是无请求体的只读 GET。调用者不提供摘要内容，不选择本地路径，不提交目标环境，也不携带要执行的命令。根控制器收到请求后，只调用新包服务的 `registry()` 并返回不可变记录。外部输入是一项读取意图，内部输入则来自构造注入的 v1845 ArchiveDigest 服务。

服务不再依赖根路由聚合器，而是直接使用 v1840 的公共 `OpsShardReadinessReleaseAcceptanceRoutePaths`。基础路径与 ConsumerPackage 相对路径保持原字节，根控制器仍通过兼容聚合器映射到相同地址。包移动不改变客户端 URL，也不新增第二份字符串所有者。路由聚合器继续受一千一百一十一行上限保护。

完整调用链是：GET 到根控制器，控制器调用 ConsumerPackage 服务，服务读取 v1845 摘要响应，然后依次生成来源快照、manifest、受众、章节、验收标准、CI 矩阵、边界锁、清单、分数卡和 Markdown，最后支持类计算总状态。响应返回后没有后台任务继续运行，也没有因读取报告而启动 Java、Node 或 mini-kv。

## 响应模型

响应开头先声明项目、版本和安全能力。`readOnly` 为真，执行、启动 Java、启动 mini-kv、读取凭据、解析原始端点和允许托管审计 HTTP 均为假。随后是 endpoint、profile、来源计划、必需归档验证计划、Operator 交接计划，以及来源摘要版本、端点、状态和消费包状态。这些字段让使用者在展开细节前确认来源和安全等级。

计数区完整列出一个来源摘要快照、五项 manifest 及通过数、四类受众及就绪数、五个章节及就绪数、五条验收标准及通过数、五项 CI 矩阵及只读数、八个边界锁及锁定数、五项交接清单及就绪数、八项分数卡及通过数、九个 Markdown 章节。计数后才是各项不可变列表、检查清单和总状态。

嵌套记录各有清楚责任。来源快照保留 v1845 版本、端点、profile、上游归档版本、摘要状态和关键数量；manifest 条目保存名称、值、是否必需和状态；受众记录角色、所有者和对应 packet；章节记录内容块、所有者和来源证据；验收标准记录代码、证据与通过标记；CI 矩阵记录批次顺序、命令族、只读与来源状态；边界锁、交接清单、分数卡和 Markdown 分别面向安全、操作、机械判定和人工阅读。

## 上游证据配置

唯一生产上游是 v1845 的 ArchiveDigest service/response。Spring 将摘要服务注入 ConsumerPackage 服务，服务调用 `registry()` 获取不可变摘要。新包不会访问 v1845 包内的摘要分区目录、重放目录或边界目录，而是只读取公开字段。上游内部可继续优化，只要公开响应不变，ConsumerPackage 就无需跟随修改。

来源摘要已经证明一个来源快照、六个摘要分区、四个预备消费包、五条只读重放指令、八个边界锁和六项分数卡满足约束。v1846 不把这些结果重新计算成另一套真相，而是做面向交接的投影。例如四类受众直接从上游四个消费包映射；五项 CI 矩阵直接从五条重放指令映射；八个边界锁直接保留上游锁定事实。

测试工厂按 v1843 到 v1846 的真实依赖顺序构造服务，最后才得到 ConsumerPackage。留根控制器测试和下游 VerificationDossier 测试只通过公开工厂获取服务，不会直接实例化包内目录。公共面因此保持为两种生产类型加一种测试辅助类型，而不是暴露整包。

## 服务层核心流程

第一步读取 v1845 摘要。第二步建立一个来源摘要快照，保留版本、端点、profile、来源归档版本、摘要状态和六、四、五、八四类核心数量。第三步生成五项 manifest：来源摘要版本、来源归档版本、来源摘要状态、来源端点和来源 profile。每项都是必需值，只有非空非白才通过，防止一份失去身份信息的包被误交接。

第四步把上游四个消费包映射成四类受众，保留 packet、owner 和 ready 状态。第五步生成五个包章节：来源摘要总览、manifest、消费包、CI 矩阵和边界锁，每节都有负责人和来源证据。第六步生成五条验收标准，分别检查来源摘要通过、摘要分区全通过、消费包全就绪、重放指令全只读、边界全锁定。

第七步把五条重放指令映射成 CI 矩阵，保留顺序、批次、命令族、只读标记和来源通过状态。第八步复制八个边界锁。第九步生成五项交接清单：读取来源摘要、确认边界锁、先跑聚焦测试、保持只读环境、归档 CI 结论。清单明确谁负责以及先后次序，避免“证据包准备好”被误解为可以跳过验证直接执行。

第十步计算八项分数卡，对 manifest、受众、章节、验收标准、CI 矩阵、边界锁、交接清单以及来源摘要分数进行数量核对。第十一步把九类结构渲染为九个 Markdown 章节。最后支持类复制所有列表，统计通过、就绪、只读和锁定数量，并以全量合取计算 `passed` 或 `blocked`。

## Java 证据检查

文件边界门要求二十三个生产文件只存在于短包，旧根路径全部消失，新包生产文件数必须恰好二十三。四个测试同样必须只存在于新测试包；根控制器和根 Markdown 聚合测试必须存在并导入短包。路径门要求包名包含 `minimalreadonlygateoperatorciconsumerpackage`，同时不包含会产生二百六十四字符目标的完整长段。

依赖门要求服务导入 v1845 摘要 service，并直接使用 v1840 RoutePaths。仍在根包等待 v1847 的十二个 VerificationDossier 生产类必须导入 ConsumerPackage 的公开 service 或 response，不得引用 manifest、audience、section 等内部目录。v1845 历史门也被推进到新包继续核对“ConsumerPackage 只消费 v1845 摘要边界”。

静态与数字门要求 SpotBugs 中响应及嵌套 Markdown 响应的四条镜像 FQN 全部转向短包，旧根 FQN 为零。根上限、精确根数和历史总门同步收紧到五百九十八；剩余非控制器必须是四百九十三，Operator-CI 桶必须是七十三，未归类必须为空，总 `ops` Java 文件不得超过一千三百五十二。

## mini-kv 证据检查

ConsumerPackage 不读取 mini-kv，也不把清单中的“run-focused-first”解释成现在执行命令。代码不启动 `minikv_cli`，不访问 RESP，不读 WAL 或快照，不写其他仓库。`startsMiniKvService` 和 `executionAllowed` 都保持为假。CI 矩阵只是从上游只读重放指令复制批次、命令族和状态，用于交接时说明应该验证什么。

mini-kv 的真实运行若要进入系统验收，必须由显式集成套件启动真实二进制、记录退出码并采集新鲜输出。本端点没有这些输入，也不产生这类输出，因此只声明“消费包保持 mini-kv 进程边界关闭”。这能防止运维页面的一次 GET 意外改变外部服务状态，也防止静态证据被写成现场联调。

从输入处理输出看，mini-kv 相关输入只是上游边界状态；处理是把只读环境和边界锁写入验收标准、CI 矩阵与交接清单；输出是结构化布尔值、条目和总状态。没有网络副作用，也没有凭据流动。

## 阻断与安全边界

服务使用 `@Transactional(readOnly = true)`，内部目录只创建不可变值。没有仓储保存、消息发布、HTTP 客户端、进程启动、部署或回滚。manifest 任一必需值空白会阻断；受众、章节、验收标准、清单任一未就绪会阻断；CI 矩阵任一非只读会阻断；边界任一未锁定会阻断；分数卡或 Markdown 数量错误也会阻断。

工程过程同样失败关闭。不能因为路径长就改类名或端点，不能删除测试来缩短路径，不能把内部类全改 public，不能复制路由，不能提高 ratchet，不能改 fixture 字节。包名缩短只解决文件系统路径，并由文档与测试固定理由。任何编译、聚焦、全量、覆盖率、格式或 SpotBugs 失败都必须在 v1846 内修复。

VerificationDossier 是明确下游，但本版不提前搬运。十二个下游类只获得公开 service/response import，为下一刀准备稳定入口。若它们需要越过边界访问内部目录，机械门会暴露设计问题，而不是让依赖悄悄扩散。

## 测试覆盖

第一次 `test-compile` 在移动、最小公开和 import 修复后直接通过，证明控制器、留根 Markdown 测试、VerificationDossier 生产与测试支持都能通过窄边界编译。原有测试继续覆盖来源快照、目录数量、边界和清单、控制器输出；新增 v1846 治理测试覆盖二十三加四精确清单、短包决策、上游与路由、十二个下游消费者、SpotBugs 和根目录数字。

聚焦套件还会运行 v1845 历史门、终局 census、全局根上限、精确根计数、维护预算和 Walkthrough 策略。讲解必须包含规定标题、version-1846、本项目和禁止硬凑标记，汉字不少于三千且占主导。历史门只从精确等于改为不超过旧值，不允许过去成果回退。

最后执行完整 `mvnw verify`，覆盖全部单元与集成测试、生产配置、架构规则、JaCoCo、Spotless 和 SpotBugs。通过后才提交实现并推送，捕获真实 CI run 后再写进度行，最后用第二提交和注释 tag 收口。下一版开始时检查本版 CI，检查点版本则等待所有远端门完成。

## 一句话总结

v1846 用路径安全的短语义包把二十三个 ConsumerPackage 实现和四个测试从根包中提取出来，把 v1845 摘要确定性地组织为 manifest、受众、章节、验收、只读 CI 矩阵、边界和交接清单，并以精确依赖、数字门与失败关闭为 v1847 VerificationDossier 提供稳定输入。
