# version-1842：发布验收包、关闭回执与归档索引完整提取

本篇对应本项目 v1842，也是当前五版检查点的最后一版。它完成的不是一个孤立类移动，而是把“发布验收路由拆分”链条最后剩余的三层职责完整收进独立维护包：第一层把持续维护证据整理为主验收包，第二层把主验收结果压缩为关闭回执，第三层把关闭回执整理为可长期复核的归档索引。三层生产实现共三十六个文件，彼此之间形成单向依赖闭包；八个包内测试与测试支持跟随实现迁移；三个 Spring 控制器和三个控制器导向测试留在根包。本文解释真实代码、真实输入输出和真实失败条件，禁止硬凑。

可以先用一条数据链把全版看清：调用者读取主验收入口，主验收服务调用 v1841 持续维护服务，生成十组结构化结果与总状态；调用者也可以读取关闭回执入口，回执服务调用主验收服务，把十组结果归纳为七项接受标准；还可以读取归档索引入口，索引服务调用回执服务，把七项接受结果展开为来源快照、标准回显、归档项、验证门和交接说明。每一层都只读上游、计算新值、复制集合并返回，不向上游写回，不执行外部命令。

## 实际工作量说明

本版迁移三十六个生产实现。主验收层包含服务、响应、支持、总渲染器、渲染支持，以及来源、谱系、决定、归档、复核、持续集成、运行边界、下一变更和评分卡九组目录或渲染器。关闭回执层包含服务、响应、接受标准目录和渲染器。归档索引层包含服务、响应、支持、总渲染器，以及来源、标准回显、归档项、验证门和交接说明五组目录。它们共享同一验收语义，且后两层依次消费前一层，所以作为一个闭包迁移比把它们拆散更能保持包内封装。

根包直接生产文件从七百三十二降到六百九十六，最终允许保留的一百零五个文件不变，仍待迁移的非控制器文件从六百二十七降到五百九十一。当前发布验收路由拆分桶从三十六降到零，说明 v1840 的基础与关闭层、v1841 的持续维护层、v1842 的验收与归档层已经全部离开根包。全部运维生产文件仍不超过一千三百五十二，未归类文件仍为零，因此这次下降来自真实移动，不是删除统计规则、复制类或遗漏目录。

八个随包测试包括主验收目录测试、不可变性测试、渲染测试、主测试支持，归档索引目录测试、不可变性测试、归档测试支持，以及关闭回执测试支持。三份留根测试分别对应主控制器、关闭回执控制器和归档索引控制器。关闭回执测试与归档索引测试同时覆盖内部输出和控制器，因此保留在根包；迁入的测试支持只公开装配服务和取得响应的最小静态方法，生产目录与渲染器仍保持包级可见。

本版还迁移了静态分析配置中的十个全限定名。十个条目来自两组镜像规则，每组覆盖主验收响应、主验收响应的章节记录、关闭回执响应、归档索引响应和归档索引章节记录。配置守卫要求新包名存在并禁止旧根包名残留，防止类移动后静态分析规则失效却无人察觉。

## 入口路由

对外仍有三个只读入口。主验收入口返回完整验收包，关闭回执入口返回七项接受标准与简洁回执，归档索引入口返回适合复核与留存的索引。三个控制器都留在根包，并继续使用 v1840 提取出的专属路由所有者：类级基础路径保持不变，方法级后缀保持不变，拼接后的地址逐字节不变。

一次普通请求不需要请求体。调用者发出读取请求，控制器只把调用转给对应服务并返回响应。控制器没有接收部署动作、凭据、数据库语句、分片写计划或兄弟项目地址。三个服务都标注只读事务，这个标记与实现中的纯目录计算共同约束链路：即使应用处于正常事务环境，也不应通过该入口改变订单、库存、支付、事件或运维记录。

包迁移后，根包控制器通过显式导入引用新包中的公开服务和公开响应。这是有意保留的最小跨包面。控制器不会导入任何目录、渲染器或支持类；内部实现也不会反向依赖控制器。这样，路由入口在根包容易查找，复杂实现被组织到维护包，依赖箭头始终从入口指向实现。

三个入口代表同一事实的不同阅读粒度。需要深入审计时读取主验收包；只想知道是否满足关闭条件时读取回执；需要长期保存和交接时读取归档索引。它们不是三个可以独立篡改状态的控制面，而是同一只读证据链的三个观察窗口。

## 响应模型

主验收响应先记录项目、版本、只读标记、执行许可、来源计划、上游持续维护版本与地址、关闭版本、基础拆分版本、当前地址和配置标识；随后记录十组数量；最后携带结构化集合、检查清单与状态。十组固定数量依次是：一份来源快照、三条版本谱系、六条决定、五个归档项、五个复核项、五条持续集成证据、七条运行边界、六条下一变更规则、九条评分卡、九个渲染章节。

每种嵌套记录只表达一种问题。来源快照回答证据从哪里来；版本谱系回答基础拆分、关闭确认和持续维护如何衔接；决定回答为何接受某项规则以及由谁负责；归档项回答保存什么、保留多久、证据是什么；复核项回答谁检查什么；持续集成证据回答哪条门、哪条命令和结果；运行边界回答哪些能力必须锁住；下一变更规则回答未来何时改、落到哪里、谁复核；评分卡把前述事实收敛成九类结论。

关闭回执响应比主验收响应更窄。它记录项目、版本、只读与执行标记、来源计划、主验收版本与地址、当前地址、配置标识、接受标准数量、渲染行数、七项标准、七行摘要、九条检查和最终状态。七项标准分别检查主验收是否通过、来源快照是否通过、所有决定是否接受、所有归档项是否就绪、持续集成证据是否通过、运行边界是否锁定、下一变更规则是否就绪。

归档索引响应面向长期复核。它记录来源回执版本与地址、来源主验收版本、当前地址和配置标识，然后给出一份来源快照、七条标准回显、五个归档项、五个验证门、四条交接说明和五个渲染章节。调用者不必重新执行整个服务链，就能从索引看出回执来源、每项标准的状态、应保存哪些对象、复核哪些门以及交接给谁。

三层支持逻辑都使用不可变复制。目录返回的列表先被复制，检查清单和状态再基于复制后的内容计算，最终响应也只暴露不可修改集合。这样可以防止外部代码在状态计算后增删条目，保证“数量、内容和状态”属于同一快照。

## 上游证据配置

主验收层唯一跨包业务上游是 v1841 的持续维护服务与响应。服务调用持续维护注册方法，得到版本、端点、关闭版本、基础拆分版本、各类守卫和状态。来源目录把它压缩为一份快照；谱系目录从中提取基础拆分、关闭确认和持续维护三个阶段；其余目录都围绕同一响应生成验收证据。没有任何目录绕回根包读取旧实现。

主验收状态会核对三个历史锚点：持续维护版本必须是既定版本，来源关闭版本必须是既定关闭契约，来源基础拆分版本必须是既定拆分契约。锚点不是当前 Git 标签，而是运行模型中的协议版本。若把错误上游接入、遗漏协议升级或只改一半版本，状态会阻断，而不会凭“字段大致相似”继续通过。

关闭回执的唯一上游是主验收服务。它要求来源状态通过、来源版本与既定主验收契约一致，并要求七项标准全部为接受。归档索引的唯一上游是关闭回执服务。它要求回执状态通过、回执版本和来源主验收版本都匹配，且来源快照、标准回显、归档项、验证门和交接说明的每个布尔条件都成立。

依赖方向因此形成清楚的阶梯：基础拆分产生路由事实，关闭层确认拆分完成，持续维护层声明长期守卫，主验收层形成综合判断，回执层形成简明关闭结论，归档索引层形成保存与交接视图。后层读取前层，前层不知道后层存在，任何未来变化都能沿单一方向评估影响。

## 服务层核心流程

主验收服务取得持续维护响应后，依次调用九组目录。来源目录生成一份快照；谱系目录生成三个阶段；决定目录生成六条接受决定；归档目录生成五个应保存对象；复核目录生成五个角色检查项；持续集成目录生成五条门证据；运行边界目录生成七条锁定项；下一变更目录生成六条未来规则；评分卡目录综合前八组结果生成九条评分。

总渲染器把九类结构化结果转成九个章节，支持类对所有列表做不可变复制，生成包含来源版本、各组数量、通过数量和禁止事项的检查清单，再计算状态。状态函数分三组条件：十个数量必须精确匹配；上游状态与三个版本锚点必须匹配；每份快照、谱系、决定、归档、复核、持续集成、运行边界、下一规则和评分都必须通过相应布尔条件。三组同时成立才返回通过，否则返回阻断。

关闭回执服务随后读取主验收响应。标准目录逐项计算七个接受条件，每项都保留名称、证据、是否必需和状态。渲染器把七项标准变成七行可读文本。服务还计算九条检查，最后要求来源状态通过、来源版本正确、七项标准全为接受，才把回执状态设为通过。回执并没有绕过主验收的细节，只是把细节压缩成可交接结论。

归档索引服务再读取回执。来源目录记录回执身份；标准目录回显七项接受结果；归档目录列出回执响应、标准台账、检查清单、渲染内容等五个保存对象；验证目录列出来源状态、版本、只读与执行边界等五个门；交接目录给出四类维护角色的使用说明；渲染器把它们整理成五个章节。支持类固定各组数量、核对来源版本并要求所有状态通过，才返回可留存结论。

以一个通俗例子说明输入输出：输入是一条不带动作参数的读取请求；主验收输出是一份详细档案，告诉你证据从何而来、检查了什么、未来怎样变；回执输出像档案封面的验收单，只列七个必须条件；归档索引输出像档案柜目录，告诉你保存哪些材料、如何复核、交给谁。任何一张单据都不能拿去执行部署，它们只证明当前证据是否自洽。

## Java 证据检查

Java 机械证据从编译器开始。三十六个实现改变包声明后，第一次主编译只指出三个留根控制器缺少六个服务/响应导入，没有内部目录跨包泄漏。补齐导入后，测试编译只指出三个留根测试需要三组测试支持和一个响应类型。把测试支持及其工厂方法设为公开后，编译通过。这个过程证明公开面由真实调用关系决定，而不是先把整个包全部设为公开。

v1842 守卫逐个枚举三十六个生产文件，要求新包存在且旧根位置不存在；逐个枚举八个迁移测试，要求新测试包存在且旧位置不存在；同时要求三个控制器和三个控制器测试仍在根包。它读取真实服务源码，确认主验收层导入 v1841 的服务与响应，关闭回执读取主验收服务，归档索引读取回执服务。

守卫还读取三个控制器，要求它们只通过新维护包的公开边界访问实现，并继续使用 v1840 路由所有者。静态分析守卫检查三类响应的新全限定名，禁止主验收响应的旧根包全限定名。计数守卫要求根包精确等于六百九十六，全部运维生产文件不超过一千三百五十二；终局清单守卫要求保留一百零五、待迁移五百九十一、拆分桶为零、未归类为空。

历史门只允许收紧。v1841 的七百三十二由当前精确值改为历史上界，v1842 持有新的六百九十六精确值；全局最大值和两个镜像精确值同步下降。没有把任何上限调高，没有删除旧版文件清单，没有修改固定响应版本或测试夹具字节。未来若根包增加一个非控制器文件，多个独立门会同时失败。

## mini-kv 证据检查

v1842 不启动、不停止、不连接也不修改 mini-kv。主验收的持续集成证据和运行边界只是结构化描述，服务没有创建子进程，没有调用 C++ 可执行文件，没有读取 mini-kv 日志、快照、预写日志或凭据。关闭回执与归档索引只消费 Java 内存中的上游响应，也不会把“归档”误解为写入兄弟仓库目录。

因此本版对 mini-kv 的运行时输入为零，运行时输出副作用也为零。Java 侧可以机械证明的是：响应执行许可为假，运行边界全部锁定，检查清单明确禁止兄弟服务启动，服务依赖图只包含 Java 内部服务和纯目录函数。它不能据此声称真实跨项目联合测试已经完成。

未来若执行系统级联合验收，应使用独立、显式启用的命令启动真实 Java 和 mini-kv，在隔离环境获取新鲜响应与命令输出，验证退出码、无写边界和进程清理。那属于系统验收能力，不应藏进当前三个公开读取入口。本版的价值是为将来的联合验收提供稳定、可消费的 Java 证据，而不是提前打开执行权限。

## 阻断与安全边界

主验收层会在任一固定数量不匹配、上游状态不通过、三个版本锚点不匹配，或任一决定未接受、归档项未就绪、复核项失败、持续集成证据失败、运行边界未锁定、下一规则未就绪、评分失败时返回阻断。这里不存在按比例通过，也不存在忽略少量失败的宽松模式。

关闭回执会在主验收状态或版本不匹配，或七项标准中任一项未接受时阻断。归档索引会在回执状态、回执版本、来源主验收版本、六组固定数量中的任一项不匹配，或任何归档项、验证门、交接说明未通过时阻断。后层不会把前层的阻断重新包装成通过。

三个响应都明确把只读设为真、执行许可设为假。边界覆盖写路由、活动分片执行、凭据值读取、原始端点解析、受管审计连接、数据库语句、部署、回滚，以及自动启动或停止 Node、Java、mini-kv。即使最终状态为通过，调用者获得的仍是证据，不是操作令牌、连接对象或执行句柄。

归档一词在这里也有严格含义：响应列出应该保存和复核的对象，接口本身不写磁盘、不移动历史归档、不改动已有证据摘要。任何真实归档动作必须由独立流程负责，并接受自己的权限、路径和一致性验证。这避免只读观察面悄悄演变为写入控制面。

## 测试覆盖

主验收目录测试验证九类证据的内容、数量和状态；不可变性测试验证所有集合不能修改；渲染测试验证九个章节与关键行。关闭回执测试验证版本、来源计划、七项标准、七行摘要、九条检查、不可变集合和控制器地址。归档索引目录测试验证来源、标准回显、归档项、验证门与交接说明；不可变性测试验证集合；渲染控制器测试同时验证五个章节和归档入口。

结构守卫覆盖文件位置、依赖方向、控制器边界、静态分析配置、根包精确计数、总量上限、终局清单和本文结构。v1841 历史守卫也随合法迁移更新读取位置，继续证明验收包消费持续维护边界，而不是因为旧路径消失就删除断言。v1840 守卫继续证明持续维护层消费关闭边界，三版证据可以串联复核。

验证顺序是：先完成实现、机械守卫、证据文档和本文，再运行格式化与聚焦测试，最后执行全量验证。全量门覆盖订单、库存、支付、事件、数据库迁移、Spring 上下文、覆盖率、格式和静态分析，确保包迁移没有影响真实业务。实施提交推送后还要由 GitHub Actions 在独立环境运行；证据提交与标签随后再触发一次远端验证。

本版遇到过一次可复现的 Windows 长路径限制。最初计划把类放入更深的三层目录，前四个较短文件移动成功，第五个长文件在改包声明前被系统拒绝。处理方式不是关闭检查或丢下半迁移状态，而是立即对账四个已移动文件和三十二个未移动文件，统一改到更短的 `releaseacceptancepackage`。短包名仍表达验收包职责，也避免以后新增同前缀类再次碰到路径上限。精确清单、编译和 Git 差异共同证明最终没有双份或漏项。

## 一句话总结

v1842 将三十六个发布验收包、关闭回执和归档索引实现及八个包内测试完整提取，在三个入口、三类响应、版本锚点和只读边界不变的前提下，把根包从七百三十二收紧到六百九十六并将该拆分桶归零，最终形成“持续维护证据进入、主验收包输出、关闭回执收敛、归档索引交接”的透明单向链。
