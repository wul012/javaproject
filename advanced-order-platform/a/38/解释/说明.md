## 合理性判断

计划合理，原因：

```text
1. 只新增 GET 只读接口，不执行 replay。
2. 不创建审批、不审核审批、不修改失败事件状态。
3. 复用 Java 现有失败事件、审批、重放审计和 RabbitMQ Outbox 配置。
4. 给 Node 后续 dry-run / preflight evidence 提供稳定 JSON。
5. 不强行绑定 Node 或 mini-kv，跨项目边界清楚。
```

因此本版直接执行，没有暂停等待确认。

## 语义说明

`blockedBy` 表示当前不允许真实重放的硬阻断，例如：

```text
FAILED_EVENT_NOT_FOUND
ALREADY_REPLAYED
REPLAY_APPROVAL_NOT_REQUESTED
REPLAY_APPROVAL_PENDING
REPLAY_APPROVAL_REJECTED
RABBITMQ_OUTBOX_DISABLED
EVENT_TYPE_REQUIRED
AGGREGATE_TYPE_REQUIRED
AGGREGATE_ID_REQUIRED
PAYLOAD_REQUIRED
```

`warnings` 表示软风险，不改变现有真实 replay 语义，例如：

```text
HAS_PREVIOUS_REPLAY_ATTEMPTS
LATEST_REPLAY_ATTEMPT_FAILED
MANAGEMENT_STATUS_IGNORED
MANAGEMENT_STATUS_RESOLVED
EVENT_ID_WILL_BE_GENERATED_IF_NOT_SUPPLIED
```

`nextAllowedActions` 用于给 Node 控制面展示下一步，例如：

```text
REQUEST_REPLAY_APPROVAL
REVIEW_REPLAY_APPROVAL
REPLAY_FAILED_EVENT
ENABLE_RABBITMQ_OUTBOX
SUPPLY_REPLAY_REQUEST_FIELDS
```
