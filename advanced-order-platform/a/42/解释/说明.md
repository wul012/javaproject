# 第四十二版：失败事件 replay execution-contract

## 计划依据

本版推进前重新读取最新计划：

```text
D:\nodeproj\orderops-node\docs\plans\v68-post-execution-gate-roadmap.md
```

计划对 Java v42 的目标是：

```text
为 failed-event replay 提供只读 execution-contract 响应，明确真实 replay 前 Java 侧会检查哪些 approval/status/digest 条件。
```

按“每版工作量合适”的规则，本轮只推进 Java v42，不同时修改 Node 或 mini-kv。

## 合理性判断

计划合理，原因：

```text
1. v42 延续 v38 readiness、v40 approval-status、v41 digest 的只读证据链。
2. execution-contract 能给 Node 后续 execution gate 提供 Java 侧契约证据。
3. 本版不新增写接口，不执行 replay，不改变审批或失败事件状态。
4. digest 边界明确为 CLIENT_PRECHECK_ONLY，不虚构真实 replay POST 已强制校验 digest。
```

因此本版直接执行，没有暂停等待确认。

## 契约语义

`executionChecks` 明确暴露真实 replay 前置条件：

```text
FAILED_EVENT_EXISTS
REPLAY_APPROVAL_APPROVED
REPLAY_ELIGIBILITY_DIGEST_AVAILABLE
FAILED_EVENT_NOT_REPLAYED
RABBITMQ_OUTBOX_ENABLED
EVENT_TYPE_PRESENT
AGGREGATE_TYPE_PRESENT
AGGREGATE_ID_PRESENT
PAYLOAD_PRESENT
```

`requestRequirements` 明确暴露真实 POST 的请求条件：

```text
reason 必填，且必须非空
eventId 可选；如果传入必须是 UUID
eventType / aggregateType / aggregateId / payload 可选覆盖；最终必须能从请求或原失败事件中得到非空值
```

digest 边界：

```text
realReplayEndpointEnforcesApprovalDigest=false
realReplayEndpointEnforcesReplayEligibilityDigest=false
digestVerificationMode=CLIENT_PRECHECK_ONLY
```

这表示真实 replay POST 当前仍由 Java 内部状态、角色、RabbitMQ 配置和请求字段做最终判断；digest 供 Node 或人工操作台在执行前复核证据是否漂移。
