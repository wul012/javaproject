# 第四十一版：失败事件 replay approval-status digest

## 计划依据

本版推进前重新读取了最新计划：

```text
D:\nodeproj\orderops-node\docs\plans\v65-post-upstream-evidence-roadmap.md
```

计划显示：

```text
Node v66 已完成 approval evidence handoff bundle
下一步 Java v41 + mini-kv v50 可并行独立推进
Java v41：approval-status 增加 evidenceVersion / approvalDigest / replayEligibilityDigest
```

按“每版工作量合适”的规则，本轮只推进 Java v41，不同时修改 mini-kv 或 Node。

## 合理性判断

计划合理，原因：

```text
1. v41 只扩展 v40 的 GET 只读响应，不新增写接口。
2. digest 能帮助 Node v67 校验 Java 上游审批证据是否漂移。
3. evidenceVersion 给后续字段演进留下兼容点。
4. 不修改数据库结构，不执行 replay，不接 Node 回调，不依赖 mini-kv。
```

因此本版直接执行，没有暂停等待确认。

## 语义说明

digest 计算排除 `sampledAt`：

```text
同一条失败事件审批状态不变时，重复读取 approval-status，digest 应保持一致。
```

`approvalDigest` 覆盖：

```text
approvalStatus
requiredApprovalStatus
approvalRequested
approvalPending
approvedForReplay
rejected
requestReason
requestedBy
requestedAt
reviewedBy
reviewedAt
reviewNote
historyCount
latestApproval
```

`replayEligibilityDigest` 覆盖：

```text
failedEventStatus
managementStatus
approvalStatus
requiredApprovalStatus
approvedForReplay
approvalBlockedBy
nextAllowedActions
```

边界：

```text
digest 只用于证据复核，不代表自动放行真实 replay。
完整重放资格仍然看 replay-readiness / replay-simulation。
```
