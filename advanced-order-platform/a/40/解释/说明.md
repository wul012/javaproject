## 合理性判断

计划合理，原因：

```text
1. v40 只新增 GET 只读接口，不执行真实 replay。
2. Java 侧已经有 replay approval 字段和 approval history 表，适合补单条 read model。
3. Node 后续 approval evidence 需要核对 Java 自己看到的审批状态，不能只依赖 Node 本地审批记录。
4. 本版不需要数据库迁移，不改审批写流程，不调用 Node，不依赖 mini-kv。
```

因此本版直接执行，没有暂停等待确认。

## 语义说明

`approval-status` 和 v38/v39 的边界：

```text
replay-readiness
 -> 判断整体能否 replay，包括审批、RabbitMQ、关键字段、是否已重放等条件

replay-simulation
 -> 在 readiness 基础上预演真实 replay 可能产生的副作用

approval-status
 -> 只读返回 Java 当前保存的 replay approval 状态和最近审批动作
```

`approvedForReplay=true` 只表示审批层面已通过，不表示真实 replay 一定能执行。真实执行前仍应结合 readiness / simulation。
