# 第四十六版：replay audit evidence 稳定样本

## 计划依据

本版推进前只读查看最新计划：

```text
D:\nodeproj\orderops-node\docs\plans\v95-production-gap-roadmap.md
```

计划里对 Java v46 的目标是：

```text
补 Java replay 审计样本，让 Node 后续能判断真实执行是否可追溯。
新增 blocked / approved replay audit sample。
明确 operator、requestId、decisionId、dryRun、executionAllowed 字段。
不开启真实 replay。
```

## 合理性判断

计划合理：

```text
1. Java v42-v45 已经提供 execution-contract、approved/blocked 样本和 ops evidence。
2. Node v98 之后需要更偏生产 readiness 的审计追溯证据。
3. 本版只新增静态样本和测试，不触发真实 replay，不修改数据库结构。
4. 本版只做 Java，不修改 Node，不修改 mini-kv。
```

因此本版执行 Java v46。

## 本版目标

新增两个静态样本：

```text
GET /contracts/failed-event-replay-audit-approved.sample.json
GET /contracts/failed-event-replay-audit-blocked.sample.json
```

approved 样本表达：

```text
dryRun=false
executionAllowed=true
approvalStatus=APPROVED
attemptStatus=SUCCEEDED
auditTrail 包含 REQUESTED -> APPROVED -> SUCCEEDED
```

blocked 样本表达：

```text
dryRun=true
executionAllowed=false
approvalStatus=PENDING
attemptStatus=NOT_ATTEMPTED
blockedBy=["REPLAY_APPROVAL_NOT_APPROVED"]
expectedSideEffects=[]
```

## 一句话总结

v46 把 replay approved 与 blocked 两种审计证据固定成静态样本，让控制面后续可以判断 Java 真实执行是否具备 operator、requestId、decisionId 和 auditTrail 追溯基础。
