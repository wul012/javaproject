## 合理性判断

计划合理，原因：

```text
1. v39 只新增 GET 只读接口，不执行真实 replay。
2. v39 可以复用 v38 readiness，避免资格判断出现两套规则。
3. 返回 wouldReplay / expectedSideEffects，能服务 Node v61 execution preview。
4. 不修改数据库结构，不依赖 Node，不依赖 mini-kv。
5. 不触碰真实 RabbitMQ 发布、审批创建、审批审核或失败事件状态变更。
```

因此本版直接执行，没有暂停等待确认。

## 语义说明

`simulation` 复用 v38 readiness 的判断：

```text
eligibleForReplay
blockedBy
warnings
nextAllowedActions
```

在此基础上新增预演字段：

```text
wouldReplay
 -> 如果现在真实执行 replay，预计是否会进入重放路径

wouldPublishOutbox
 -> 如果现在真实执行 replay，预计是否会尝试发布 RabbitMQ Outbox 消息

wouldChangeManagementStatus
 -> 当前真实 replay 逻辑不会修改 failed event managementStatus，因此固定为 false

expectedSideEffects
 -> 预计真实 replay 可能产生的副作用说明
```

当事件具备重放条件时，预计副作用为：

```text
PUBLISH_RABBITMQ_REPLAY_MESSAGE
SAVE_REPLAY_ATTEMPT_AUDIT
MARK_FAILED_EVENT_REPLAYED_ON_SUCCESS
MARK_FAILED_EVENT_REPLAY_FAILED_ON_BROKER_ERROR
```
