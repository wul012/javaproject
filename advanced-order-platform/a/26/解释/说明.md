# 开发运行调试 v26：修复默认健康检查误报 DOWN

## 本次目标

v25 冒烟留下一个小问题：默认本地启动时页面和 API 正常，`/actuator/health/liveness` 与 `/actuator/health/readiness` 都是 `UP`，但根 `/actuator/health` 是 `DOWN`。

v26 处理这个问题，让默认本地模式的健康检查只检查当前真正启用的能力。

## 原因判断

项目引入了：
```xml
<artifactId>spring-boot-starter-amqp</artifactId>
```

即使默认配置里：
```yaml
outbox.rabbitmq.enabled: false
notification.rabbitmq.enabled: false
```

Spring Boot 仍可能因为 AMQP 依赖创建 RabbitMQ 连接工厂，并让 Actuator Rabbit health indicator 加入根 health 聚合。默认本地没有启动 RabbitMQ，所以根 health 会被 Rabbit 探针拖成 `DOWN`。

## 代码改动

默认配置关闭 Rabbit health：
```yaml
management:
  health:
    rabbit:
      enabled: false
```

RabbitMQ profile 重新开启 Rabbit health：
```yaml
management:
  health:
    rabbit:
      enabled: true
```

新增测试：
```text
src/test/java/com/codexdemo/orderplatform/ActuatorHealthIntegrationTests.java
```

测试断言：
```text
/actuator/health           -> UP
/actuator/health/liveness  -> UP
/actuator/health/readiness -> UP
```

## 本版结论

v26 是一个工程化修复版：默认本地开发不启用 RabbitMQ，就不让 RabbitMQ 健康探针影响根健康检查；启用 rabbitmq profile 时，再把 RabbitMQ 纳入健康判断。
