# 第四十五版：订单平台 ops evidence 只读运行证据

## 计划依据

本版推进前依照最新计划目录只读判断方向：

```text
D:\nodeproj\orderops-node\docs\plans\v95-production-gap-roadmap.md
```

计划里对 Java v45 的目标是：

```text
新增只读 ops evidence endpoint，输出 failed-event replay 状态、outbox 状态、
approval/execution blocker 状态、service version/profile、readOnly、
executionAllowed=false，不触发真实 replay，不修改订单状态。
```

## 合理性判断

计划合理：

```text
1. Java v42-v44 已经提供 execution-contract 和 approved/blocked 样本。
2. 下一步需要一个更上层的聚合证据接口，方便控制面先读 Java 状态。
3. 本版只做 Java，不修改 Node，不修改 mini-kv。
4. 接口只读，风险适中，工作量适合作为一个独立小版本。
```

因此本版执行 Java v45。

## 本版目标

新增接口：

```text
GET /api/v1/ops/evidence
```

核心语义：

```text
readOnly=true
executionAllowed=false
evidenceVersion=java-ops-evidence.v1
service.name=advanced-order-platform
service.version=0.1.0-SNAPSHOT
failedEventReplay.replayBacklog=当前未重放失败事件数量
outbox.publisherEnabled=当前 Outbox 发布器开关
outbox.rabbitMqEnabled=当前 RabbitMQ Outbox 开关
approvalExecution.requiredApprovalStatus=APPROVED
blockers=当前只读证据接口和执行前阻断原因
warnings=当前风险提示
```

## 一句话总结

v45 把 Java 订单平台的服务版本、失败事件重放、审批门禁、Outbox 状态和执行阻断原因聚合成只读证据接口，为后续控制面安全接入提供稳定 Java 契约。
