# v83 运行说明

## 1. 版本目标

Java v83 不是新增业务协议，而是继续拆分 `OpsEvidenceService` 的职责，把 release approval rehearsal 的 verification hint 构造抽到独立 builder。

这次抽出的部分包括：

- `verificationHint` 构造
- `warningDigest`
- `proofClaims`
- `nodeVerificationActions`
- `noLedgerWriteProved`

## 2. 拆分结果

新增：

```java
ReleaseApprovalVerificationHintBuilder
```

它接收已有的各类 receipt / hint，负责生成：

- `RehearsalVerificationHint`
- warning digest
- proof claims
- node verification actions
- schema field 列表

`OpsEvidenceService` 现在只负责把各个 receipt 串起来，再把对象交给 builder。

## 3. 不变项

本次拆分没有改这些内容：

- 响应字段名
- digest 算法
- digest 输入顺序
- proof claims 语义
- node verification action 语义
- read-only / no-ledger / no-SQL / no-connection 边界

## 4. 代码规模

拆完后：

- `OpsEvidenceService` 从 3666 行降到 3110 行
- `ReleaseApprovalVerificationHintBuilder` 新增 693 行
- `ReleaseApprovalManagedAuditSandboxAdapterApprovalSchemaGuardReceiptBuilder` 保持 419 行

这是一次明显的主服务瘦身，但 `OpsEvidenceService` 仍然偏大，后面还可以继续把更多 release approval 片段抽成专用 builder。
