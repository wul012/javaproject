# 开发运行调试 v66：release approval rehearsal 只读聚合入口

## 计划依据

最新计划 `D:\nodeproj\orderops-node\docs\plans\v182-post-rehearsal-quality-roadmap.md` 已确认 Node v183-v184 完成，推荐并行 Java v66 + mini-kv v75。其中 Java v66 目标是补 `release approval rehearsal` 的只读运行聚合入口，不执行审批、不写 ledger、不回滚、不执行 SQL。

本轮只推进 Java 项目，不处理 mini-kv。

## 合理性判断

合理。v65 已经提供 rollback approver evidence fixture，但 Node v185 real-read rehearsal intake 需要更接近真实运行的 Java 聚合视图。本版不再横向新增静态 fixture，而是复用 `/api/v1/ops/evidence` 里的现有 live evidence，增加一个动态只读入口，工作量适中。

## 本版目标

- 新增 `GET /api/v1/ops/release-approval-rehearsal`。
- 新增 `ReleaseApprovalRehearsalResponse`，分组表达 `releaseApprovalInputs`、`liveSignals` 和 `executionBoundaries`。
- 将新入口接入 `healthProbe.additionalProbeEndpoints`、`readOnlyWindow.allowedProbeEndpoints`、`releaseAuditRetentionFixture.evidenceEndpoints` 和 `evidenceEndpoints`。
- 补服务层测试与 MVC 集成测试。
- 补 README、代码讲解和运行归档。

## 代码改动

- `OpsOverviewController` 增加 `/release-approval-rehearsal` GET 路由。
- `OpsEvidenceService` 增加 `RELEASE_APPROVAL_REHEARSAL_VERSION`、`RELEASE_APPROVAL_REHEARSAL_ENDPOINT` 和 `releaseApprovalRehearsal()`。
- `OpsEvidenceService` 通过现有 `evidence()` 聚合 release approval 输入、live replay/outbox 信号、执行边界、blockers 和下一步 evidence actions。
- 新增 `ReleaseApprovalRehearsalResponse` record。
- 更新 `OpsEvidenceServiceTests` 和 `OpsOverviewIntegrationTests`。
