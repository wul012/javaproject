# v79 运行说明

## 1. 版本目标

Java v79 在 `/api/v1/ops/release-approval-rehearsal` 上新增 `opsEvidenceServiceQualitySplitReceipt`。它承接 Node v218 的 audit route + managed-audit helper quality pass，并给 Node v219 managed audit adapter implementation precheck 提供 Java 侧质量收口回执。

这一版不是生产 adapter wiring，也不是大规模搬迁 `OpsEvidenceService`。它先把后续拆分边界写进只读响应，明确 receipt / digest / hint / render / record 各自职责，避免真实 adapter 准备阶段继续把所有责任堆进一个大类。

```text
Node v218 audit route + managed-audit helper quality pass
 -> Java v79 OpsEvidenceService quality split receipt
 -> Node v219 managed audit adapter implementation precheck
```

## 2. 新增字段

`ReleaseApprovalRehearsalResponse` 顶层新增：

```java
RehearsalOpsEvidenceServiceQualitySplitReceipt opsEvidenceServiceQualitySplitReceipt
```

核心字段：

```text
sourceProductionAdapterPrerequisite*
 -> 证明它消费的是 Java v78 production adapter prerequisite receipt

consumedByNodeQualityPass*
 -> 固定 Node v218 quality pass 版本和 profile

nextNodePrecheck*
 -> 指向 Node v219 implementation precheck

responsibilityBoundaries / safeSplitSequence / deferredSplitReasons
 -> 标注 receipt、digest、hint、render、record 的拆分顺序和暂缓原因

apiShapeChanged / approvalLedgerWritten / sqlExecuted / managedAuditStoreWritten
 -> 全部保持 false
```

## 3. 生成逻辑

`OpsEvidenceService.releaseApprovalRehearsal(...)` 在 v78 receipt 之后生成 v79 receipt：

```java
rehearsalOpsEvidenceServiceQualitySplitReceipt(managedAuditProductionAdapterPrerequisiteReceipt)
```

ready 条件是：上游 v78 receipt ready，且所有生产动作、写 ledger、SQL、部署、回滚、restore、真实 managed audit 连接都保持关闭。

没有完整 header 时，`receiptWarnings` 会包含：

```text
NODE_V219_SOURCE_PRODUCTION_ADAPTER_PREREQUISITE_RECEIPT_NOT_READY
```

传入完整 header 后，`readyForNodeV219ImplementationPrecheck=true`，但仍不代表生产审计、生产窗口或真实 adapter 连接授权。
