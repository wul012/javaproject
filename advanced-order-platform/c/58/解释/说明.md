# v58 开发运行调试说明

## 版本目标

本版依据 `D:\nodeproj\orderops-node\docs\plans\v166-post-rollback-window-roadmap.md` 推进 Java v58：增加 production rollback SQL review gate sample，把 rollback SQL review owner、migration direction、operator approval placeholder 和生产库访问边界固化成只读 gate。

本版只做 Java 项目内部的只读 SQL review gate，不执行 rollback SQL，不连接生产数据库，不读取生产密钥，不改变订单交易语义。

## 代码改动

- `OpsEvidenceResponse` 增加 `RollbackSqlReviewGate` record。
- `OpsEvidenceService` 增加 `java-rollback-sql-review-gate.v1` 常量、`rollbackSqlReviewGate()` 和 review gate 静态端点挂接。
- 动态 `/api/v1/ops/evidence` 增加 `rollbackSqlReviewGate` 字段。
- 新增 `src/main/resources/static/contracts/rollback-sql-review-gate.sample.json`。
- 更新 `ops-read-only-evidence.sample.json`、`ops-evidence-field-guide.sample.json`、`deployment-rollback-evidence.sample.json`、`release-bundle-manifest.sample.json`、`rollback-approval-handoff.sample.json` 和 `release-verification-manifest.sample.json`，把 SQL review gate 纳入只读证据链。
- 更新 `README.md` 记录 v58 的 review gate 用途。

## 关键边界

- `gateMode=READ_ONLY_SQL_REVIEW_GATE`：只读 review gate，不执行 SQL。
- `reviewOwner=database-release-owner`：记录 SQL review 责任位。
- `migrationDirectionOptions=forward-only / rollback-script-reviewed / no-database-change`：迁移方向必须人工选择。
- `operatorApprovalPlaceholder=operator-approval-required-before-any-sql-execution`：真实审批记录不由样本生成。
- `nodeMayTriggerRollback=false`：Node 只能消费 review gate，不能触发 Java rollback。
- `sqlExecutionAllowed=false`：样本不能执行数据库回退 SQL。
- `requiresProductionDatabase=false`：样本和本地 smoke 不需要生产库。
- `changesOrderTransactionSemantics=false`：不改变订单、库存、支付、Outbox 或 replay 事务语义。
