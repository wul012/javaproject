# v76 运行调试说明

## 版本目标

本版按最新计划 `D:\nodeproj\orderops-node\docs\plans\v211-post-managed-audit-packet-roadmap.md` 推进 Java v76：为 `/api/v1/ops/release-approval-rehearsal` 增加只读 `approvalHandoffVerificationMarker`，标注 Node v211 已消费 Java v75 approval-record handoff 的 dry-run packet 覆盖和 no-write 边界，供后续 Node v213 restore drill plan 前置核对。

## 主要改动

- `ReleaseApprovalRehearsalResponse` 新增 `approvalHandoffVerificationMarker`。
- `OpsEvidenceService` 新增 `rehearsalApprovalHandoffVerificationMarker(...)`，并把 schema 升级到 `java-release-approval-rehearsal-response-schema.v10`。
- marker 固定回显 Node v211 dry-run packet profile、endpoint、requestId、packet version、`.tmp` 目录标签、文件名前缀和 JSONL 文件名。
- marker 记录 Node v211 append/query/digest/cleanup 覆盖，同时声明 Java write、mini-kv write、external audit、真实 approval decision、真实 ledger 和 production audit record 均未发生。
- `verificationHint` 新增 marker schema field、warning digest input 和 no-write proof claim。
- 单元测试和 HTTP 集成测试覆盖缺省 header、完整 header、warning digest 稳定性、Node v213 ready marker 和 no-ledger/no-production-audit 边界。
- README 与代码讲解文档补充 v76 说明。

## 关键边界

- Java 不创建 approval decision。
- Java 不写 approval ledger。
- Java 不持久化 approval record。
- Java 不写 managed audit store。
- Java 不连接外部 audit system。
- Java 不执行 restore。
- Java 不触发 deployment、rollback 或 rollback SQL。
- Java 不读取生产 secret。
- `readyForNodeV213RestoreDrillPlan=true` 只表示 Node 可进入 restore drill plan 设计前置检查，不代表可执行 restore。
- `nodeV211ProductionAuditRecordAllowed=false` 明确说明这不是生产 audit record。
