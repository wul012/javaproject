# 开发运行调试 v65：rollback approver evidence fixture

## 计划依据

最新计划 `D:\nodeproj\orderops-node\docs\plans\v179-post-pre-approval-roadmap.md` 指定下一阶段推荐并行 Java v65 + mini-kv v74。其中 Java v65 要补 `rollback approver evidence fixture`，记录 rollback approver、migration direction、SQL/no-SQL boundary 和 production database boundary。

本轮只推进 Java 项目，不处理 mini-kv。

## 合理性判断

合理。v64 已经有 release operator signoff fixture，但后续 Node v182 做 release approval decision rehearsal packet 前，还需要更明确的 rollback approver、rollback SQL artifact reference 和生产数据库边界。本版正好补这份只读证据，不扩大到真实审批、ledger、rollback 或 SQL。

## 本版目标

- 新增动态 evidence 字段 `rollbackApproverEvidenceFixture`。
- 新增静态 contract：`/contracts/rollback-approver-evidence.fixture.json`。
- 将新 fixture 接入 release verification、release bundle、deployment rollback、release handoff checklist、release audit retention、release operator signoff、rollback approval handoff、rollback approval record、production deployment runbook、ops read-only evidence 和 field guide。
- 补充服务层测试与 MVC 集成测试。
- 补充 README、代码讲解和运行归档。

## 代码改动

- `OpsEvidenceResponse` 增加 `RollbackApproverEvidenceFixture` record。
- `OpsEvidenceService` 增加 v65 版本常量、endpoint 常量、`rollbackApproverEvidenceFixture()` 和 `rollbackApproverEvidenceArtifacts()`。
- 新增 `rollback-approver-evidence.fixture.json` 静态样本。
- 更新多份静态 contract 样本，确保新 endpoint 能被 Node 后续只读消费。
- 扩展 `OpsEvidenceServiceTests` 与 `OpsOverviewIntegrationTests`，验证动态字段、静态 endpoint、SQL 执行禁止、生产库禁止和 approval decision 禁止边界。
