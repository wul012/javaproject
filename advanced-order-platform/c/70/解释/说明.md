# 开发运行调试 v70：release approval rehearsal 只读 operator-window hint

## 计划依据

最新计划 `D:\nodeproj\orderops-node\docs\plans\v197-post-readiness-checkpoint-roadmap.md` 是当前唯一有效全局计划。计划说明 Node v198 real-read window operator identity binding 已完成，下一步推荐并行 Java v70 + mini-kv v79。

本轮只推进 Java v70，不修改 mini-kv。

## 合理性判断

合理。Node v198 已经定义真实只读窗口请求需要 operator id、roles、verified claim 和 approval correlation id。Java v70 在 release approval rehearsal 的只读响应中回显这些字段，能让 Node 后续确认 Java 上游是否看见同一组身份线索。版本工作量适中，只增加 echo/hint 和测试，不接入认证、不写持久化、不改变订单交易语义。

## 本版目标

- `ReleaseApprovalRehearsalResponse` 新增 `operatorWindowHint`。
- `operatorWindowHint.hintVersion` 固定为 `java-release-approval-rehearsal-operator-window-hint.v1`。
- 支持读取并回显：
  - `x-orderops-operator-id`
  - `x-orderops-roles`
  - `x-orderops-operator-verified`
  - `x-orderops-approval-correlation-id`
- 缺失字段写入 `operatorWindowHint.echoWarnings`。
- 完整字段时返回 `operatorWindowContextComplete=true`。
- 继续固定：
  - `productionIdpVerifiedByJava=false`
  - `persistedApprovalRecordByJava=false`
  - `nodeMayTreatAsProductionIdentity=false`
- `verificationHint.responseSchemaVersion` 升级为 `java-release-approval-rehearsal-response-schema.v4`。
- `verificationHint.warningDigestInputs` 增加 `operatorWindowEchoWarnings`。

## 代码改动

- `OpsOverviewController` 读取 Node v198 的四个 `x-orderops-*` header。
- `ReleaseApprovalRehearsalResponse` 增加 `RehearsalOperatorWindowHint` record。
- `OpsEvidenceService` 增加 operator-window hint 常量、构造逻辑、缺失 warning 和 v4 schema。
- `OpsEvidenceServiceTests` 覆盖缺失 header 与完整 header 两种 service 路径。
- `OpsOverviewIntegrationTests` 覆盖 HTTP JSON 中 `operatorWindowHint.*` 字段。
- `README.md` 增加 v70 使用说明和阶段进度。
- `代码讲解记录_生产雏形阶段/74-version-70-release-approval-operator-window-hint.md` 增加多代码引用讲解。
