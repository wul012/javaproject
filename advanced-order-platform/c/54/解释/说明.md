# Java v54 开发运行调试说明

## 计划来源

本版推进前已读取最新计划：

```text
D:\nodeproj\orderops-node\docs\plans\v161-post-controlled-idempotency-drill-roadmap.md
```

计划判断：合理。当前推荐步骤是 Java v54 做 `release verification manifest`，固化 Maven 聚焦测试、非 Docker 回归、package、HTTP smoke 和静态 contracts 清单；不改订单业务语义，不接生产数据库，不接 mini-kv。

## 本版目标

v54 目标是让 Java release 前验证证据可复现、可被 Node 只读消费：

```text
Java 本地执行并归档
 -> focused-maven-tests
 -> non-docker-regression-tests
 -> maven-package
 -> http-smoke
 -> static-contract-json-validation

Node 后续只读消费
 -> 读取 Java v54 tag
 -> 读取 release verification manifest
 -> 读取 c/54 归档证据
 -> 不替 Java 执行 Maven
 -> 不触发 Java 写接口
```

本版明确不做：

```text
不改变 POST /api/v1/orders 语义
不改变支付、库存、Outbox、失败事件 replay 事务
不接 mini-kv
不接生产数据库
不打开任何 Node 写操作权限
```

## 代码改动

新增静态发布验证 manifest：

```text
src/main/resources/static/contracts/release-verification-manifest.sample.json
```

manifest 固定说明：

```text
manifestVersion=java-release-verification-manifest.v1
scenario=JAVA_RELEASE_VERIFICATION_MANIFEST_SAMPLE
verificationChecks=focused-maven-tests, non-docker-regression-tests, maven-package, http-smoke, static-contract-json-validation
staticContracts=5 个随包静态契约
releaseGate.nodeMayExecuteMaven=false
releaseGate.nodeMayTriggerJavaWrites=false
boundaries.changesOrderCreateSemantics=false
boundaries.connectsMiniKv=false
archiveExpectation.runtimeArchiveRoot=c/<version>
```

`OpsEvidenceResponse` 新增：

```text
releaseVerification
```

`OpsEvidenceService` 新增只读 evidence 字段：

```text
releaseVerification.manifestVersion=java-release-verification-manifest.v1
releaseVerification.manifestEndpoint=/contracts/release-verification-manifest.sample.json
releaseVerification.verificationMode=LOCAL_OPERATOR_EXECUTES_AND_ARCHIVES_RESULTS
releaseVerification.nodeMayExecuteBuild=false
releaseVerification.nodeMayTriggerWrites=false
releaseVerification.changesBusinessSemantics=false
releaseVerification.requiresProductionSecrets=false
```

同时把 manifest endpoint 挂到：

```text
healthProbe.additionalProbeEndpoints
readOnlyWindow.allowedProbeEndpoints
evidenceEndpoints
ops-read-only-evidence.sample.json
ops-evidence-field-guide.sample.json
```

## Docker 与清理

本版没有新增 Flyway 迁移，没有修改 PostgreSQL / RabbitMQ 配置，也没有进入 Testcontainers 场景，所以未启动 Docker。

清理结果：

```text
HTTP smoke 临时 Java 进程已停止
端口 18096 已释放
临时 smoke 日志已删除
Docker 未启动，无需关闭
```

## 成熟度变化

v54 把 Java 发布前验证从“临时命令集合”提升为“随包发布验证 manifest”。后续 Node v162 可以只读消费这份 manifest 和 `c/54` 归档，形成跨项目 release verification gate，而不需要直接执行 Java Maven 或触发 Java 写操作。

## 一句话总结

Java v54 固化了 release verification manifest，让 Maven 测试、打包、HTTP smoke 和静态 contracts 清单成为可复现、可归档、可被 Node 只读消费的发布验证证据。
