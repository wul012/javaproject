# 开发运行调试 v68：release approval rehearsal 只读失败分类

## 计划依据

最新计划 `D:\nodeproj\orderops-node\docs\plans\v191-post-real-read-adapter-roadmap.md` 已确认 Node v192 完成，下一步推荐并行 Java v68 + mini-kv v77。其中 Java v68 目标是在 release approval rehearsal 只读入口中补失败分类字段，让 Node 能区分 upstream readiness、auth-context warning、audit-correlation warning 等情况。

本轮只推进 Java 项目，不处理 mini-kv。

## 合理性判断

合理。v66 已提供只读聚合入口，v67 已补 request id、operator identity 和 audit correlation 的只读请求上下文；v68 在同一个响应中补 failure taxonomy，能直接服务 Node v193 的真实只读 adapter failure taxonomy。版本工作量适中，只增加一个 response 分组、一个 service 分类方法和测试断言，不做大重构。

## 本版目标

- `ReleaseApprovalRehearsalResponse` 新增 `failureTaxonomy`。
- `failureTaxonomy.taxonomyVersion` 固定为 `java-release-approval-rehearsal-failure-taxonomy.v1`。
- 分类 upstream readiness、auth context readiness、audit correlation readiness。
- 默认无 header 时返回 `AUTH_CONTEXT_WARNING` 与 `AUDIT_CORRELATION_WARNING`。
- header 齐全时上下文 warning 消失，但 `READ_ONLY_EXECUTION_BLOCKED` 保留。
- 明确 `retryableByReadOnlyAdapter=true`、`writeActionRequired=false`。
- 补服务层测试与 MVC 集成测试。
- 补 README、代码讲解和运行归档。

## 代码改动

- `ReleaseApprovalRehearsalResponse` 增加 `RehearsalFailureTaxonomy` record。
- `OpsEvidenceService` 增加 `RELEASE_APPROVAL_REHEARSAL_FAILURE_TAXONOMY_VERSION`。
- `OpsEvidenceService.releaseApprovalRehearsal(...)` 统一 normalize header 后同时构造 `requestContext` 与 `failureTaxonomy`。
- `OpsEvidenceService` 增加 `releaseApprovalRehearsalFailureTaxonomy(...)` 和 `readinessStatus(...)`。
- `OpsEvidenceServiceTests` 验证默认 warning 分类、header 齐全分类和 no-write 边界。
- `OpsOverviewIntegrationTests` 验证 HTTP JSON 中 `failureTaxonomy.*` 字段。
- `README.md` 和 `代码讲解记录_生产雏形阶段/72-version-68-release-approval-failure-taxonomy.md` 补说明。
