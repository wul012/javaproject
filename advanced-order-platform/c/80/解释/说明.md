# v80 运行说明

## 1. 版本目标

Java v80 按 Node 最新计划 `docs/plans/v219-post-implementation-precheck-roadmap.md` 推进，在 `/api/v1/ops/release-approval-rehearsal` 上新增 `managedAuditAdapterImplementationGuardReceipt`。

它承接 Node v220 `managed audit adapter disabled shell`，给 Node v221 local file/sqlite adapter candidate dry-run 提供 Java 侧只读 guard digest：

```text
Node v220 managed audit adapter disabled shell
 -> Java v80 managed audit adapter implementation guard receipt
 -> Node v221 managed audit local adapter candidate dry-run
```

本版不是生产 adapter wiring，不连接真实外部 managed audit，不执行 Java approval / ledger / SQL / deployment / rollback / restore。

## 2. 新增字段

`ReleaseApprovalRehearsalResponse` 顶层新增：

```java
RehearsalManagedAuditAdapterImplementationGuardReceipt managedAuditAdapterImplementationGuardReceipt
```

核心字段：

```text
sourceQualitySplit*
 -> 来源是 Java v79 OpsEvidenceService quality split receipt，source schema 固定为 v13

consumedByNodeDisabledShell*
 -> 固定 Node v220 disabled shell 版本、profile、endpoint 和 disabled-shell-ready 状态

nextNodeCandidate*
 -> 指向 Node v221 local adapter candidate dry-run

guardDigest
 -> Java v80 对 source receipt、Node v220 disabled shell no-write 事实、Java no-write 字段生成的稳定 sha256 digest

readyForNodeV221LocalAdapterCandidateDryRun
 -> 仅表示 Node v221 可以消费 guard 后做本地 file/sqlite candidate dry-run，不代表生产审计授权
```

## 3. 安全边界

v80 明确保持：

```text
managedAuditAdapterImplementationGuardReceipt.nodeV220SelectedAdapterDisabled=true
managedAuditAdapterImplementationGuardReceipt.nodeV220LocalDryRunOnlyDeclared=true
managedAuditAdapterImplementationGuardReceipt.nodeV220AppendWritten=false
managedAuditAdapterImplementationGuardReceipt.nodeV220QueryReturnedRecords=false
managedAuditAdapterImplementationGuardReceipt.nodeV220ExternalManagedAuditAccessed=false
managedAuditAdapterImplementationGuardReceipt.nodeV220LocalDryRunWritePerformed=false
managedAuditAdapterImplementationGuardReceipt.javaApprovalDecisionCreated=false
managedAuditAdapterImplementationGuardReceipt.javaApprovalLedgerWritten=false
managedAuditAdapterImplementationGuardReceipt.javaApprovalRecordPersisted=false
managedAuditAdapterImplementationGuardReceipt.javaManagedAuditStoreWritten=false
managedAuditAdapterImplementationGuardReceipt.javaSqlExecuted=false
managedAuditAdapterImplementationGuardReceipt.javaDeploymentTriggered=false
managedAuditAdapterImplementationGuardReceipt.javaRollbackTriggered=false
managedAuditAdapterImplementationGuardReceipt.javaRestoreExecuted=false
managedAuditAdapterImplementationGuardReceipt.readyForProductionAudit=false
managedAuditAdapterImplementationGuardReceipt.readyForProductionWindow=false
managedAuditAdapterImplementationGuardReceipt.nodeMayTreatAsProductionAuditRecord=false
```

没有完整 Node v210 approval binding header 时，上游 v79 receipt 不 ready，因此 v80 guard 也不 ready，并返回：

```text
NODE_V221_SOURCE_OPS_EVIDENCE_SERVICE_QUALITY_SPLIT_RECEIPT_NOT_READY
```

传入完整 header 后，`readyForNodeV221LocalAdapterCandidateDryRun=true`，但仍只允许 Node v221 写 `.tmp` 或明确测试目录里的本地 dry-run 记录。
