# v57 开发运行调试说明

## 版本目标

本版依据 `D:\nodeproj\orderops-node\docs\plans\v163-post-rollback-readiness-roadmap.md` 推进 Java v57：增加 rollback approval handoff sample，固化 Java 回退窗口前必须由人工确认的 artifact version、runtime config、secret source、database migration direction、release bundle 和 deployment rollback evidence 字段。

本版只做 Java 项目内部的只读审批交接样本，不执行 rollback SQL，不读取生产密钥，不连接生产数据库，不改变订单交易语义。

## 代码改动

- `OpsEvidenceResponse` 增加 `RollbackApprovalHandoff` record。
- `OpsEvidenceService` 增加 `java-rollback-approval-handoff.v1` 常量、`rollbackApprovalHandoff()` 和 handoff 静态端点挂接。
- 动态 `/api/v1/ops/evidence` 增加 `rollbackApprovalHandoff` 字段。
- 新增 `src/main/resources/static/contracts/rollback-approval-handoff.sample.json`。
- 更新 `ops-read-only-evidence.sample.json`、`ops-evidence-field-guide.sample.json`、`deployment-rollback-evidence.sample.json`、`release-bundle-manifest.sample.json` 和 `release-verification-manifest.sample.json`，把 handoff 纳入只读证据链。
- 更新 `README.md` 记录 v57 的 handoff 用途。

## 关键边界

- `approvalMode=OPERATOR_CONFIRMATION_REQUIRED`：必须人工确认，不自动执行。
- `nodeMayTriggerRollback=false`：Node 只能消费 handoff，不能触发 Java rollback。
- `rollbackSqlExecutionAllowed=false`：样本不能执行数据库回退 SQL。
- `requiresProductionDatabase=false`：样本和本地 smoke 不需要生产库。
- `requiresProductionSecrets=false`：样本不读取生产密钥值。
- `changesOrderTransactionSemantics=false`：不改变订单、库存、支付、Outbox 或 replay 事务语义。
