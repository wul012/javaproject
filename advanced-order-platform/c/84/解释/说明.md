# v84 运行说明

## 1. 版本目标

Java v84 继续做 release approval rehearsal 的 contract-preserving refactor，不新增业务 receipt，也不改变 Node 可消费的响应契约。

目标是继续给 `OpsEvidenceService` 减负，把已经稳定的 managed-audit receipt 构造链和 verification warning digest 拆到专用 builder。

## 2. 拆分结果

新增：

```java
ReleaseApprovalDigestSupport
ReleaseApprovalVerificationWarningDigestBuilder
ReleaseApprovalManagedAuditAdapterBoundaryReceiptBuilder
ReleaseApprovalManagedAuditProductionAdapterPrerequisiteReceiptBuilder
ReleaseApprovalOpsEvidenceServiceQualitySplitReceiptBuilder
ReleaseApprovalManagedAuditAdapterImplementationGuardReceiptBuilder
```

调整：

- `OpsEvidenceService` 只串联 v77-v82 receipt builder，不再内联 v77-v80 的长构造方法。
- `ReleaseApprovalVerificationHintBuilder` 不再内联 warning digest 计算，改为委派给 `ReleaseApprovalVerificationWarningDigestBuilder`。
- `ReleaseApprovalManagedAuditSandboxAdapterApprovalSchemaGuardReceiptBuilder` 复用 `ReleaseApprovalDigestSupport`，避免重复 SHA-256 / canonical line helper。

## 3. 不变项

本次拆分保持以下内容不变：

- release approval rehearsal API 路径
- 响应字段名和 record 结构
- schema version 字段值
- warning digest 输入顺序
- proof claims
- Node verification actions
- read-only / no-ledger / no-SQL / no-connection / no-credential 边界

## 4. 代码规模

拆完后：

- `OpsEvidenceService` 从 3110 行降到 2605 行，减少 505 行
- `ReleaseApprovalVerificationHintBuilder` 从 693 行降到 445 行
- 新增 builder/support 文件承接稳定构造逻辑

这次拆分幅度比 v83 更大，但仍限制在 release approval rehearsal 的已稳定构造链内，没有把早期 header hint、failure taxonomy 或 response record 一起移动。
