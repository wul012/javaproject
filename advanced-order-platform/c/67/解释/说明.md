# 开发运行调试 v67：release approval rehearsal 只读请求上下文

## 计划依据

最新计划 `D:\nodeproj\orderops-node\docs\plans\v185-post-real-read-rehearsal-roadmap.md` 已确认 Node v186-v190 完成，推荐并行 Java v67 + mini-kv v76。其中 Java v67 目标是对 v66 的 release approval rehearsal 做持久化/认证前置只读证据增强，不执行审批或 ledger 写入。

本轮只推进 Java 项目，不处理 mini-kv。

## 合理性判断

合理。v66 已经提供动态只读聚合入口；v67 不继续堆静态 fixture，而是补真实调用时需要的 request id、operator identity 和 audit correlation 字段。为了保持版本工作量适中，本版只做只读 header 回显和来源标注，不接入真实 IdP、不建表、不写 ledger。

## 本版目标

- `GET /api/v1/ops/release-approval-rehearsal` 支持可选只读 header：
  - `X-Rehearsal-Request-Id`
  - `X-Operator-Identity`
  - `X-Audit-Correlation-Id`
- `ReleaseApprovalRehearsalResponse` 新增 `requestContext`。
- `requestContext.contextVersion` 固定为 `java-release-approval-rehearsal-context.v1`。
- 无 header 时返回稳定占位和 `contextWarnings`。
- 有 header 时 trim 后回显，并标注来源 header。
- 明确 `operatorAuthenticatedByJava=false`、`persistedByJava=false`、`approvalLedgerWritten=false`。
- 补服务层测试与 MVC 集成测试。
- 补 README、代码讲解和运行归档。

## 代码改动

- `OpsOverviewController` 为 `/release-approval-rehearsal` 增加三个可选 `@RequestHeader`。
- `ReleaseApprovalRehearsalResponse` 增加 `RehearsalRequestContext` record。
- `OpsEvidenceService` 增加 `releaseApprovalRehearsal(requestId, operatorIdentity, auditCorrelationId)` 重载。
- `OpsEvidenceService` 增加 `rehearsalRequestContext`、`normalizeHeaderValue`、`valueOrPlaceholder`、`sourceFor`、`addMissingContextWarning`。
- `OpsEvidenceServiceTests` 验证默认占位、warning、header trim 和 no-ledger 边界。
- `OpsOverviewIntegrationTests` 验证 HTTP header 到 JSON response 的真实映射。
