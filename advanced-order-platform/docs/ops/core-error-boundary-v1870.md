# v1870 核心错误边界优化

## Family design

- 抽象名：`BusinessException.Kind`，只表达业务失败类别，不携带 HTTP 类型。
- 数据边界：`BusinessException` 保存失败类别、稳定错误码和可读消息。
- 行为边界：`ApiExceptionHandler` 独占失败类别到 HTTP 状态的映射。
- 查询边界：过期订单批次由短名仓储方法和显式分页共同表达。
- 机械边界：非 Controller 的订单与库存源码不得导入 Spring HTTP。

## 失败条件

- `BusinessException`、订单核心或库存核心仍直接导入 `HttpStatus`。
- 三种失败类别没有穷尽映射到 400、404、409。
- 过期订单查询不再限制 50 条，或失去按创建时间升序的语义。
- 为通过门禁而提高命名、源码增长、文件尺寸或 SpotBugs 上限。
- 完整 `mvnw verify`、远端 CI 或中文讲解门任一失败。
