# v1810 操作员证据取值供给·签批·捕获工件预检注册表迁出代码讲解（J20）

本版本是 v1796 清查之后的第十三刀契约保持型整理，编号 J20。它把“操作员证据取值供给·签批·捕获工件预检”这一注册表家族从根 `ops` 包迁入新建的 `ops.maintenance.signedapprovalcaptureartifactpreflight` 子包，共搬动十六个非控制器实现文件，两个对外控制器与全局路由聚合类继续留在根包。所有路由字符串、响应结构与只读语义逐字节不变。这份讲解先于完整验证写成，逐项据实陈述，绝不把字数留到验证之后才补，也禁止硬凑凑数。

需要先交代背景。签批家族是一张相互缠绕的大网，包含工件草稿、指令预检、复核打包、文本包录入、捕获预检、捕获工件预检等十余个兄弟家族。早在 v1804 那一刀，我已经把其中三个家族的路由常量类（含本刀的捕获工件预检路由常量类）抽出到 `ops.maintenance.signedapproval` 子包并改为公开类。因此本刀与前面几刀的不同之处在于：本家族的路由常量类早已外迁且公开，迁移服务实现时无需新建路由常量类，只要让服务改指那个早已就位的公开常量类即可。这正是选它作为本刀目标的关键原因——它的路由侧成本最低。

## 入口路由

捕获工件预检家族对外暴露两个控制器（基础控制器与保障控制器），合计十余条只读注册表路由，覆盖目录、捕获摘要、模板复核、操作员片段、捕获策略、签名封缄、声明证据、脱敏取值、失败即锁、归档计划、收尾等通道。每条路由由共享基础路径拼接上一段以“取值供给·签批·捕获工件预检”为前缀的后缀常量构成。

迁移前，家族内每个服务读取的是全局路由聚合类上的后缀常量与基础路径，而全局聚合类对这些后缀的取值，实际是委派转发到 v1804 already 外迁的公开族路由常量类。迁移时，因为服务搬进子包后再也无法访问包级可见的全局聚合类，我把每个服务对全局聚合类的引用整体改指到那个公开族路由常量类；又因为该族路由常量类此前只持有后缀常量、并没有基础路径常量，我给它补上了一个公开的基础路径常量，取值与全局聚合类完全一致。两个控制器仍留在根包，继续从全局聚合类读取后缀，因此控制器的路由声明无需改动；全局聚合类对这些后缀的委派也保持不变。由于族路由常量类的后缀常量名与全局聚合类委派的常量名逐字一致，这一步本质上只是把类名前缀换掉，路由取值不动。

## 响应模型

家族的响应记录随家族一起迁入子包，聚合目录条目、捕获摘要、模板复核结论、操作员片段、捕获策略片段、签名封缄、声明证据、脱敏取值、失败即锁等只读字段，并附带渲染后的段落文本，全部使用不可变集合。迁移不改动任何响应字段、顺序或不可变语义，只改变它们所在的包。值得记录的是：本家族的响应记录没有触发静态分析的可控暴露豁免条目，静态分析豁免清单里没有与本家族相关的条目，因此本刀无需像早期几刀那样搬迁豁免条目，这也侧面印证了该响应记录使用的是拷贝式不可变构造。

## 上游证据配置

本家族在路由侧自成一体，不读取任何别家族的路由常量，这一点已经过事前核对并被完整编译复核。真正的跨家族耦合只有一处，且方向有两路。

出向一路：家族内的“片段目录”实现文件，会引用十个“捕获预检”兄弟家族服务的端点常量，用于在自身证据输出里交叉引用捕获预检的只读路由地址。涉及的兄弟服务包括通道签名策略、收尾、失败即锁、操作员输入镜像、脱敏溯源绑定、复核摘要绑定、来源证据镜像、声明理由、模板摘要绑定、时序窗口等十个。为让这条耦合在新的包边界上仍然成立，我把这十个捕获预检服务的端点常量改为公开，并在迁入子包后的片段目录文件里补齐对应导入。

入向一路：仍然留在根包的“工件草稿就绪”兄弟家族的两个条目目录，以及它的一个支撑测试，会读取本家族若干服务的端点常量。为让这些留守根包的读取方在跨包后仍能编译通过，我把本家族全部服务的端点常量统一改为公开。

需要强调的是，这种跨家族端点子配方与早期“自成一体、零跨家族边”的做法有本质区别，必须谨慎评估它的代价与边界。放开端点常量的可见性，意味着把一个家族原本仅供包内使用的实现细节暴露给相邻家族，这在架构上是一种受控的妥协：只在两个家族确实存在以路由交叉引用为形式的证据耦合时才这样做，且严格限定在端点常量这一层，不波及任何业务方法或内部状态。换个角度看，这些被读取的端点其实代表的是“另一条只读证据路由的地址”，当前以服务端点常量的形式传递只是历史实现的权宜；本刀在不改变行为的前提下先让耦合跨过包边界，未来若把相邻的捕获预检家族、工件草稿就绪家族也迁入同一维护子包群，这些跨包引用就会重新收敛为包内引用，可见性也可以再次收紧。正因为看清了这条演进路径，我才判断这一刀的可见性放开是可接受且可回收的，而不是不可逆的污染。

## 服务层核心流程

家族内每个服务在初始化时把族路由常量类的基础路径拼接上自己的后缀常量得到只读端点，再依据目录、模板、片段、封缄、台账等只读数据组装结果，交由渲染器与支撑类拼成响应。迁移没有改动任何业务逻辑，只把服务读取路由常量的来源从包级可见的全局聚合类改为公开的族路由常量类，并把片段目录对捕获预检兄弟端点的读取从根包跨到了导入声明上。

之所以必须改来源，是因为全局聚合类是包级可见的，搬到子包后的服务无法再访问它。事前普查已确认家族读取的聚合路由常量全部是本家族自有的捕获工件预检后缀，没有夹带任何属于别家族的聚合内联常量，因此一次整体替换即可把它们统一改指到族路由常量类，不会误伤。这一点与候选文档那一刀遇到的“聚合内联跨家族常量”不同，本刀在路由维度上是干净的。

## Java 证据检查

Java 侧证据检查依旧“编译先行、分步收敛”，而本刀恰好提供了一个值得诚实记录的教训。事前我用单行正则普查家族的出向端点引用，结论是“零跨家族端点边”，于是一度以为这是一刀纯净的迁移。但仅编译第一遍就立刻推翻了这个结论：片段目录文件其实引用了十个捕获预检兄弟服务，只是源码把类名写在一行、把 `.ENDPOINT` 写在下一行，跨行折行的写法让单行正则彻底漏看。教训很明确——服务端点的跨行折行格式会骗过单行端点普查，真正可靠的边界仍然是完整编译。我据此把那十个兄弟端点改为公开并补齐导入。

仅测试编译又暴露出两处：迁走的片段目录测试仍引用包级可见的全局聚合类基础路径，迁走的支撑测试仍引用一个捕获预检兄弟服务端点。我把前者改指公开族路由常量类并补导入，把后者补上对应导入。两轮编译收敛后，第三步交由完整验证流水线统一校验：单元测试全绿、各包覆盖率地板满足、静态分析零新增、代码风格零违规。治理阈值方面，根包直接文件数从一千一百三十七降到一千一百二十一；我同步把三处计数护栏全部下调到一千一百二十一——治理计划护栏、v1806 收尾镜像护栏，以及 v1809 迁移测试里那处精确计数断言。这三处都是对根包目录文件数的实时统计，必须同刀一起下调，否则其中任一处都会让验证失败。

## mini-kv 证据检查

本次迁移与 mini-kv 没有任何关系。捕获工件预检家族是只读证据接口，不发起任何连接，也不读写任何键值。家族内若有涉及 mini-kv 的陈述，也仅停留在只读响应里对证据边界的描述层面，迁移不会触发 mini-kv 的真实连接或自动启动。

因此可以明确：本版本对 mini-kv 的运行时行为零影响，既不改变连接语义，也不改变任何存储读写语义。整刀只是把相关类换了一个包、把族路由常量类补上公开基础路径、把跨家族端点按可见性放开，不触及任何网络或存储动作。

## 阻断与安全边界

本版本严格守住既有安全边界。它不打开任何写路由、不路由活跃分片、不读取凭据值、不解析原始端点地址、不建立受管审计的网络连接、不部署、不回滚、不触发 Java 或 mini-kv 的自动启动。它所做的全部，就是把家族换包、给早已外迁的族路由常量类补上公开基础路径、把片段目录读取的十个捕获预检兄弟端点与本家族被回读的端点按需公开、并为跨包引用补齐导入。

归档边界同样不可触碰：本次迁移不重命名也不移动任何归档根目录，从 `a/` 到 `f/`、形如 `e/<version>/` 的目录、各类证据 JSON、截图归档以及历史代码讲解目录都原地不动，Node 侧对 Java 证据归档的引用因此不会失效。

## 测试覆盖

测试侧按职责拆分：保障控制器测试、基础控制器测试、路由常量测试三者留在根包，因为它们要么断言留在根包的控制器，要么断言全局聚合类与族路由常量类、各服务端点之间的等价关系；它们改为导入迁入子包后的类型。另有六个纯家族内测试随家族迁入测试子包，分别覆盖保障服务、基础服务、片段目录、闸门目录、封缄目录与支撑类。

为防止回退，本版本新增专门守护测试，逐一断言代表性实现文件确实位于新子包、不再出现在根包，并断言两个控制器与全局聚合类仍留在根包；同时以“不高于一千一百二十一”的非回归方式守护根包计数，避免再增一处必须逐刀维护的精确计数断言。

## 实际工作量说明

本节据实说明工作量，绝不夸大，也禁止硬凑字数。本次真实改动包括：用版本控制移动十六个家族实现文件、改写其包声明、把家族内对全局聚合类的路由引用整体改指到公开族路由常量类；给该族路由常量类补上公开基础路径；按跨家族端点子配方把十个捕获预检兄弟服务端点公开并在片段目录补齐导入、把本家族全部服务端点公开以服务于留守根包的工件草稿就绪条目目录与支撑测试；为两个控制器、三个留守根包测试补齐对迁走类型的导入；迁移六个家族内测试并修正其中两处跨包引用；新增迁移说明文档、迁移守护测试、变更日志条目、进度行、子目录索引与本讲解；下调三处根包计数护栏。

这一刀的难点不在体量，而在那个被单行普查漏掉、最终靠完整编译逼出来的跨行端点边。它再次说明：契约保持型迁移的安全，不能寄托于事前正则的乐观结论，而要让编译器作为最终裁判。本项目正是通过这种“编译先行、逐层收敛”的纪律，才在路由取值逐字节不变的前提下安全完成了又一刀跨家族迁移。

## 一句话总结

本项目在 v1810 把操作员证据取值供给·签批·捕获工件预检注册表家族迁入新建的 `ops.maintenance.signedapprovalcaptureartifactpreflight` 子包，根包直接文件数从一千一百三十七降到一千一百二十一，服务改指 v1804 已外迁的公开族路由常量类（仅补公开基础路径），并以仅放开可见性的跨家族端点子配方处理片段目录对十个捕获预检兄弟端点的读取与工件草稿就绪家族对本族端点的回读，所有路由取值与只读语义逐字节不变。
