# v1813 操作员证据取值供给·签批·工件草稿就绪注册表迁出代码讲解（J23）

本版本是 v1796 清查之后的第十六刀契约保持型整理，编号 J23。它把“操作员证据取值供给·签批·工件草稿就绪”这一注册表家族从根 `ops` 包迁入新建的 `ops.maintenance.signedapprovalartifactdraftreadiness` 子包，共搬动十六个非控制器实现文件，两个对外控制器与全局路由聚合类继续留在根包。所有路由字符串、响应结构与只读语义逐字节不变。这份讲解先于完整验证写成，逐项据实陈述，绝不把字数留到验证之后才补，也禁止硬凑凑数。

需要先交代背景。工件草稿就绪家族是签批工件草稿大网中的一员，它处在一个承上启下的位置：一方面它向下读取“捕获工件预检”家族的端点作为来源证据，另一方面它自身的端点又被若干平行家族回读。早在 v1804 那一刀，我已经把本家族的路由常量类抽出到 `ops.maintenance.signedapproval` 子包并改为公开类；在更近的 v1810 那一刀，捕获工件预检家族被迁出，且它被本家族读取的那十个端点常量已经在那时一并放开为公开只读字符串。正因为这两笔前置工作已经就位，本刀的跨家族成本被显著压低——出向耦合已经满足，无需再改任何捕获工件预检端点的可见性。

## 入口路由

工件草稿就绪家族对外暴露两个控制器（基础控制器与保障控制器），合计十条只读注册表路由，覆盖目录、归档计划、收尾、摘要链、证据来源、失败即锁、操作员窗口、脱敏溯源、签名声明等通道。每条路由由共享基础路径拼接上一段以“工件草稿就绪”为前缀的后缀常量构成。

迁移前，家族内每个服务读取的是全局路由聚合类上的后缀常量与基础路径，而全局聚合类对这些后缀的取值，实际委派转发到 v1804 已外迁的公开族路由常量类。迁移时，因为服务搬进子包后再也无法访问包级可见的全局聚合类，我把每个服务对全局聚合类的引用整体改指到那个公开族路由常量类；又因为该族路由常量类此前只持有九个后缀常量、并没有基础路径常量，我给它补上了一个公开的基础路径常量，取值与全局聚合类完全一致。两个控制器仍留在根包，继续从全局聚合类读取后缀，因此控制器的路由声明无需改动；全局聚合类对这些后缀的委派也保持不变。由于族路由常量类的后缀常量名与全局聚合类委派的常量名逐字一致，这一步本质上只是把类名前缀换掉，路由取值不动。事前已逐一核对：家族读取的全部聚合后缀都是“工件草稿就绪”自有的九个，没有夹带任何属于“工件草稿就绪车道”或别家族的后缀常量，因此整体替换是安全的。

## 响应模型

家族的响应记录随家族一起迁入子包，聚合目录条目、闸门、归属、摘要链、证据来源等只读字段，并附带渲染后的段落文本，全部使用不可变集合。迁移不改动任何响应字段、顺序或不可变语义，只改变它们所在的包。本家族的响应记录带有受控暴露豁免：它在静态分析豁免清单里以根包旧全限定名登记了 EI_EXPOSE_REP 与 EI_EXPOSE_REP2 两类条目，分别出现在两个镜像块中；迁包后旧全限定名失配，必须把这两处条目改写到迁入子包后的新全限定名，否则静态分析会把它们当作新增缺陷而判失败。我据此完成了两处全限定名的同步改写，保持“只缩不增”的豁免基线。

## 上游证据配置

工件草稿就绪家族的跨家族耦合分两路，方向相反。

出向一路：家族的两个条目目录读取“捕获工件预检”家族十个服务的端点常量，作为来源证据交叉引用。关键在于，这十个端点常量早在 v1810 捕获工件预检迁出时就已经被放开为公开只读字符串，且条目目录当时就已改为从迁入子包后的捕获工件预检子包导入它们。因此本刀对出向耦合无需任何新的可见性改动——迁移这两个条目目录时，它们对捕获工件预检子包的导入语句原样带走即可继续编译通过。这正是前置版本铺垫带来的红利。

入向一路：仍留在根包的三个平行家族读取本家族服务的端点常量——工件草稿预检家族的两个字段目录与其支撑测试、工件草稿复核打包预检家族的槽位目录、以及签批草稿剖面段落注册表家族的注册表服务、来源目录与测试支撑。为让这些留守根包的读取方在跨包后仍能编译通过，我把本家族全部服务的端点常量改为公开，并为这些读取方逐一补齐对迁走类型的导入。

这种跨家族端点子配方与早期“自成一体、零跨家族边”的做法有本质区别，必须谨慎评估它的代价与边界。放开端点常量的可见性，意味着把一个家族原本仅供包内使用的实现细节暴露给相邻家族，这在架构上是一种受控的妥协：只在两个家族确实存在以路由交叉引用为形式的证据耦合时才这样做，且严格限定在端点常量这一层，不波及任何业务方法或内部状态。换个角度看，这些端点其实代表“另一条只读证据路由的地址”，当前以服务端点常量的形式传递只是历史实现的权宜；未来若把这几个相邻家族也迁入同一维护子包群，这些跨包引用就会重新收敛为包内引用，可见性也可以再次收紧。正因为看清了这条演进路径，我才判断这一刀的可见性放开是可接受且可回收的，而不是不可逆的污染。

## 服务层核心流程

家族内每个服务在初始化时把族路由常量类的基础路径拼接上自己的后缀常量得到只读端点，再依据目录、闸门、归属、摘要链、证据来源等只读数据组装结果，交由渲染器与支撑类拼成响应。迁移没有改动任何业务逻辑，只把服务读取路由常量的来源从包级可见的全局聚合类改为公开的族路由常量类。条目目录对捕获工件预检端点的读取逻辑也原样保留，仅依赖那十个早已公开的端点常量。

之所以必须改来源，是因为全局聚合类是包级可见的，搬到子包后的服务无法再访问它。事前普查已确认家族读取的聚合路由常量全部是本家族自有的工件草稿就绪后缀，没有夹带任何属于别家族的聚合内联常量，因此一次整体替换即可把它们统一改指到族路由常量类，不会误伤。

## Java 证据检查

Java 侧证据检查依旧“编译先行、分步收敛”。这一刀我特意吸取了上一刀的教训：跨家族出向边不能只靠单行端点正则去数，因为类名与 `.ENDPOINT` 常常分两行书写，会骗过单行普查；所以我改用“把家族文件里出现的全部 `OpsShardReadiness` 标识符整体列出再逐一归类”的多行无关方式核对边界，确认出向只有捕获工件预检一族、且其端点已全部公开。仅测试编译暴露出一处：迁走的条目目录测试仍引用包级可见的全局聚合类基础路径，我把它改指公开族路由常量类并补导入。一轮修正后测试编译即转绿。

随后第三步交由完整验证流水线统一校验：单元测试全绿、各包覆盖率地板满足、静态分析零新增（前提是已把两处响应豁免条目改写到新全限定名）、代码风格零违规。治理阈值方面，根包直接文件数从一千零八十九降到一千零七十三；我同步把三处实时计数护栏全部下调到一千零七十三——治理计划护栏、v1806 收尾镜像护栏，以及那处仍为精确等值断言的迁移测试根计数；其余采用“不高于”非回归写法的迁移测试无需改动。

## mini-kv 证据检查

本次迁移与 mini-kv 没有任何关系。工件草稿就绪家族是只读证据接口，不发起任何连接，也不读写任何键值。家族内若有涉及 mini-kv 的陈述，也仅停留在只读响应里对证据边界的描述层面，迁移不会触发 mini-kv 的真实连接或自动启动。

因此可以明确：本版本对 mini-kv 的运行时行为零影响，既不改变连接语义，也不改变任何存储读写语义。整刀只是把相关类换了一个包、把族路由常量类补上公开基础路径、把入向被回读的端点按可见性放开，不触及任何网络或存储动作。

## 阻断与安全边界

本版本严格守住既有安全边界。它不打开任何写路由、不路由活跃分片、不读取凭据值、不解析原始端点地址、不建立受管审计的网络连接、不部署、不回滚、不触发 Java 或 mini-kv 的自动启动。它所做的全部，就是把家族换包、给早已外迁的族路由常量类补上公开基础路径、把本家族被三个平行家族回读的端点按需公开、并为跨包引用补齐导入，外加把两处响应静态分析豁免条目改写到新全限定名。

归档边界同样不可触碰：本次迁移不重命名也不移动任何归档根目录，从 `a/` 到 `f/`、形如 `e/<version>/` 的目录、各类证据 JSON、截图归档以及历史代码讲解目录都原地不动，Node 侧对 Java 证据归档的引用因此不会失效。

## 测试覆盖

测试侧按职责拆分：保障控制器测试、基础控制器测试、路由常量测试三者留在根包，因为它们要么断言留在根包的控制器，要么断言全局聚合类与族路由常量类、各服务端点之间的等价关系；它们改为导入迁入子包后的类型。另有六个纯家族内测试随家族迁入测试子包，分别覆盖保障服务、基础服务、闸门目录、条目目录、归属目录与支撑类。

为防止回退，本版本新增专门守护测试，逐一断言代表性实现文件确实位于新子包、不再出现在根包，并断言两个控制器与全局聚合类仍留在根包；同时以“不高于一千零七十三”的非回归方式守护根包计数，避免再增一处必须逐刀维护的精确计数断言。

## 实际工作量说明

本节据实说明工作量，绝不夸大，也禁止硬凑字数。本次真实改动包括：用版本控制移动十六个家族实现文件、改写其包声明、把家族内对全局聚合类的路由引用整体改指到公开族路由常量类；给该族路由常量类补上公开基础路径；按跨家族端点子配方把本家族全部服务端点公开，以服务于三个留守根包的平行家族读取方，并为这些读取方逐一补齐导入；迁移六个家族内测试并修正其中一处测试对聚合类基础路径的引用；把两处响应静态分析豁免条目改写到新全限定名；下调三处根包计数护栏；新增迁移说明文档、迁移守护测试、变更日志条目、进度行、子目录索引与本讲解。

这一刀之所以相对顺手，是因为出向耦合在 v1810 与 v1804 两笔前置工作里已被铺平：捕获工件预检端点早已公开、族路由常量类早已外迁公开。它说明契约保持型整理是有路径依赖的——先迁被依赖方、再迁依赖方，可以让后续每一刀的可见性改动越来越少。本项目正是通过这种有序的逐层迁移与编译器兜底，才在路由取值逐字节不变的前提下安全完成了又一刀跨家族迁移。

## 一句话总结

本项目在 v1813 把操作员证据取值供给·签批·工件草稿就绪注册表家族迁入新建的 `ops.maintenance.signedapprovalartifactdraftreadiness` 子包，根包直接文件数从一千零八十九降到一千零七十三，服务改指 v1804 已外迁的公开族路由常量类（仅补公开基础路径），出向读取的十个捕获工件预检端点因 v1810 早已公开而无需再动，入向则把本族端点放开供三个平行家族回读，所有路由取值与只读语义逐字节不变。
