# v1807 操作员证据取值草稿注册表迁出代码讲解（J17）

本版本是 v1796 清查之后的第十刀契约保持型整理，也是第一刀真正启用“跨家族端点子配方”的迁移。它把操作员证据取值草稿注册表家族从根 `ops` 包迁入新建的 `ops.maintenance.operatorevidencevaluedraft` 子包，共搬动十六个非控制器实现文件以及家族路由常量类，两个对外控制器与全局路由聚合类继续留在根包。所有路由、响应结构与只读语义逐字节不变。需要先说明编号：v1806 是 Codex 完成的纯文档质量收尾，没有移动任何代码，被记为 J16；本刀是其后真正移动文件的迁移，记为 J17。这份讲解先于完整验证写成，逐项据实陈述，绝不把字数留到验证之后才补，也禁止硬凑凑数。

与 v1799 到 v1805 那些自成一体的家族不同，取值草稿家族身处操作员证据这一相互缠绕的子系统中，存在双向端点耦合，必须显式处理——但处理方式仅限于放开可见性、补充导入，绝不改动任何路由字符串。之所以选它作为本刀目标，是因为在仍留在根包的几个大家族里，它的真实跨家族边数最少、且自带家族路由常量类，迁移代价相对可控。

## 入口路由

取值草稿家族对外暴露两个控制器（基础控制器与保障控制器），合计十余条只读注册表路由，涵盖目录、槽位模板、指令集、校验边界、安全闸门矩阵、来源映射注册表、阻断原因台账、摘要蓝图、路由画像摘要、操作员交接、归档计划、收尾等通道。每条路由由共享基础路径拼接上一段以取值草稿为前缀的后缀常量构成。

这些后缀常量原本由家族路由常量类持有、并由全局聚合类逐一委派转发，而家族文件读取时走的是全局聚合类。迁移时我把家族路由常量类搬入新子包、改为公开类、补上公开的基础路径常量、把全部后缀常量公开；随后把家族文件里对全局聚合类的路由常量引用整体改指到家族路由常量类。两个控制器仍留在根包，继续从全局聚合类读取后缀，因此控制器的路由声明无需改动；全局聚合类对这些后缀的委派保持不变，只是改为从迁入子包后的家族路由常量类取值。

## 响应模型

家族的响应记录随家族一起迁入子包，聚合目录条目、槽位模板、指令、安全闸门、来源映射、阻断原因、摘要蓝图、校验结果等只读字段，并附带渲染后的段落文本，全部使用不可变集合。迁移不改动任何响应字段、顺序或不可变语义，只改变它们所在的包。涉及受控暴露豁免的响应条目，我把静态分析豁免清单里相关条目改写到迁入子包后的新类名前缀，保持“只缩不增”的豁免基线。

## 上游证据配置

取值草稿家族读取上游发布审批预演证据来组装各通道的只读结果，这部分逻辑不变。真正需要显式处理的是它与兄弟家族之间的端点耦合，方向有两路。出向一路：取值草稿的目录类读取七个证据导入预检家族服务的端点常量（目录、收尾、导入阻断矩阵、缺失值守卫、脱敏保留、槽位归一、目标范围映射），用于在自身证据输出里交叉引用导入预检的路由。入向一路：根包里仍然保留的取值供给槽位目录，以及取值草稿自己的路由守护测试，读取取值草稿各服务的端点常量。

为让这两路耦合在新的包边界上仍然成立，我把出向涉及的七个导入预检服务端点常量改为公开，并在迁入子包后的取值草稿文件里补齐导入；又把取值草稿各服务的端点常量改为公开，使留在根包的取值供给槽位目录与守护测试仍能跨包读取。这一切只是放开可见性加补导入，端点取值没有任何变化，路由常量本身依旧经由未改动的全局聚合类流转。

值得强调的是，这种跨家族端点子配方与之前几刀“自成一体、零跨家族边”的做法有本质区别，因此必须谨慎评估它的代价与边界。放开端点常量的可见性，意味着把一个家族原本仅供包内使用的实现细节暴露给相邻家族，这在架构上是一种受控的妥协：只有当两个家族确实存在以路由交叉引用为形式的证据耦合时才这样做，且严格限定在端点常量这一层，不波及任何业务方法或内部状态。换个角度看，这些被读取的端点其实代表的是“另一条只读证据路由的地址”，本应通过共享的路由常量来传递，而当前以服务端点常量的形式传递只是历史实现的权宜；本刀在不改变行为的前提下先让耦合跨过包边界，未来若把相邻家族也迁入同一维护子包，这些跨包引用就会重新收敛为包内引用，可见性也可以再次收紧。正因为看清了这条演进路径，我才判断这一刀的可见性放开是可接受且可回收的，而不是不可逆的污染。

## 服务层核心流程

家族内每个服务在初始化时把家族路由常量类的基础路径拼接上自己的后缀常量得到只读端点，再依据目录、模板、闸门、台账等只读数据组装结果，交由渲染器与支撑类拼成响应。迁移没有改动任何业务逻辑，只把服务读取路由常量的来源从包级可见的全局聚合类改为公开的家族路由常量类。

之所以必须改来源，是因为全局聚合类是包级可见的，搬到子包后的服务无法再访问它。事前普查已确认：家族文件读取的聚合路由常量全部是取值草稿自有的后缀加基础路径，没有夹带任何属于别家族的聚合内联常量，因此一次整体替换即可把它们统一改指到家族路由常量类，不会误伤。这一点与上一刀候选文档迁移中遇到的“聚合内联跨家族常量”不同，本刀在这一维度上是干净的，跨家族耦合全部集中在服务端点常量这一层，并已按子配方逐一放开可见性。

## Java 证据检查

Java 侧证据检查依旧“编译先行、分步收敛”。仅编译先暴露出两个留在根包的控制器与取值供给槽位目录引用了迁走的类型，我据此补齐导入；仅测试编译又暴露出守护测试读取的若干取值草稿端点常量仍是包级可见、以及一个取值供给测试与一个迁走的支撑测试缺少导入，我据此把取值草稿全部端点常量统一公开、并为相关测试补齐导入。两轮编译收敛后，第三步交由完整验证流水线统一校验：单元测试全绿、各包覆盖率地板满足、静态分析零新增、代码风格零违规。治理阈值方面，根包直接文件数从一千一百八十三降到一千一百六十七，我把治理护栏阈值同步下调到一千一百六十七。

这里要诚实记录一处与普查口径有关的偏差：自动普查最初按“仅统计服务端点常量与类引用”的口径，把入向耦合低估为一个文件，但实际上那个取值供给槽位目录读取了八个取值草稿端点常量，守护测试还另读了更多。最终是靠完整编译把这些读点逐一逼了出来，我索性把取值草稿的全部端点常量统一公开以彻底覆盖，避免反复试错。

## mini-kv 证据检查

本次迁移与 mini-kv 没有任何关系。取值草稿家族是只读证据接口，不发起任何连接，也不读写任何键值。家族内若有涉及 mini-kv 的陈述，也仅停留在只读响应里对证据边界的描述层面，迁移不会触发 mini-kv 的真实连接或自动启动。

因此可以明确：本版本对 mini-kv 的运行时行为零影响，既不改变连接语义，也不改变任何存储读写语义。整刀只是把取值草稿相关类换了一个包，并把跨家族端点耦合按可见性放开，不触及任何网络或存储动作。

## 阻断与安全边界

本版本严格守住既有安全边界。它不打开任何写路由、不路由活跃分片、不读取凭据值、不解析原始端点地址、不建立受管审计的网络连接、不部署、不回滚、不触发 Java 或 mini-kv 的自动启动。它所做的全部，就是把取值草稿家族换包、把家族路由常量类与相关端点常量按需公开、并为跨包引用补齐导入。

归档边界同样不可触碰：本次迁移不重命名也不移动任何归档根目录，从 `a/` 到 `f/`、形如 `e/<version>/` 的目录、各类证据 JSON、截图归档以及历史代码讲解目录都原地不动，Node 侧对 Java 证据归档的引用因此不会失效。

## 测试覆盖

测试侧按职责拆分：两个测试留在根包，因为它们要么断言留在根包的控制器，要么断言全局聚合类的包级常量与各服务端点；它们改为导入迁入子包后的类型。两个纯家族内测试随家族迁入测试子包。另有一个取值供给家族的支撑测试留在根包，它经由公开后的端点常量引用迁走的取值草稿服务。

为防止回退，本版本新增专门守护测试，逐一断言代表性实现文件确实位于新子包、不再出现在根包，并断言两个控制器与全局聚合类仍留在根包；治理阈值守护测试则把根包直接文件数从一千一百八十三收紧到一千一百六十七。

## 实际工作量说明

本节据实说明工作量，绝不夸大，也禁止硬凑字数。本次真实改动包括：用版本控制移动十六个家族实现文件与家族路由常量类、改写其包声明、把家族内对聚合类的引用整体改指到家族路由常量类；把家族路由常量类公开、补公开基础路径、公开后缀常量；按跨家族端点子配方把七个导入预检服务端点与取值草稿各服务端点公开，并在出入两向补齐导入；迁移两个家族内测试、为留守根包的控制器与测试补齐导入；把静态分析豁免条目改写到新类名；下调治理阈值；新增守护测试、迁移说明文档、变更日志、进度行、子目录索引与本讲解。

这一刀的难点在于跨家族耦合的收敛：必须先量化出真实边数最小的家族，再用完整编译把普查口径之外的端点读点逼出来，最后只用“放开可见性加补导入”这种零行为变更的方式把双向耦合安全地跨越新的包边界。本项目正是通过这种逐层验证，才在契约逐字节不变的前提下完成了第一刀跨家族迁移。

## 一句话总结

本项目在 v1807 把操作员证据取值草稿注册表家族迁入新建的 `ops.maintenance.operatorevidencevaluedraft` 子包，根包直接文件数从一千一百八十三降到一千一百六十七，首次以仅放开可见性的跨家族端点子配方处理双向耦合，所有路由取值与只读语义逐字节不变。
