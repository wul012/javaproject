# v1803 沙箱连接注册表家族抽离代码讲解（J13）

本版本是 v1796 清查之后的第七刀契约保持型类迁移，也是走出代码讲解家族后的第三刀。它在结构上有两个新意义：第一，这是继凭据解析器之后的第二个依赖注入式“证据”注册表家族；第二，这是迄今第一次在一个版本里整体迁出“同时拥有两个控制器、两套注册表子簇、且这两套子簇共享同一个路由常量类”的家族。被迁移的家族是沙箱连接相关的两条只读证据接口：一条是被阻断执行上下文归一化档案，另一条是上游回执校验清单的预检。本次讲解先于验证写成，确保不把字数留到验证之后才补，从根上杜绝把讲解当成走过场、禁止硬凑凑数的做法。

本版本的核心目标依旧是缓解根 `ops` 包的体积压力。做法是把家族里除控制器以外的二十六个文件，从扁平的根包整体搬入更窄的维护子包，而对外暴露的两条路由、两个响应模型、所有只读语义保持逐字节不变。下面按既定的十节结构逐项说明本次改动的来龙去脉与边界。

## 入口路由

家族对外暴露两条只读路由，二者共享同一个基础路径前缀，再各自拼接自己的后缀常量。第一条是被阻断执行上下文归一化档案路由，第二条是上游回执校验清单预检路由。这两条路由原本由家族自带的路由常量类持有后缀，再由根部的全局路由聚合类做一次转发声明，方便老的调用方继续从聚合类读取同名常量。

本次迁移把家族的路由常量类一起搬进了新的维护子包，并把这个常量类、它的基础路径常量以及两个后缀常量统一改为公开可见。这样一来，仍然留在根包的两个控制器可以通过导入子包里的公开常量来继续标注请求映射；根部的全局聚合类也通过新增一行子包导入，继续把这两条后缀转发出去。换句话说，路由字符串本身一个字符都没有改动，改的只是这些常量声明所在的物理位置与可见性级别，调用契约因此完全延续。

## 响应模型

家族包含两个响应记录类型，分别对应两条路由的返回结构。被阻断执行上下文档案的响应聚合了来源回执、上下文字段、前置证据、边界快照、执行护栏、告警回声、下游接收闸门、校验闸门、交接说明以及若干段落化的渲染文本。上游回执校验清单预检的响应则聚合了来源回执、拆分模块、证据引用、预检字段、边界护栏、代码健康闸门、校验闸门、交接说明以及渲染段落。

这两个响应记录连同它们内部的嵌套记录一起迁入子包，字段顺序、字段命名、不可变集合语义都没有变化。由于响应类对外暴露的列表此前已被静态分析工具按受控方式接受，迁移时必须把这些可见性接受项跟着类的全限定名一起搬家，否则同样的可见性提示会以新的全限定名重新出现而触碰静态分析阈值。本次共迁移了十一条接受项到新的全限定名，而那些记录类型本身并不搬家，因此与它们对应的接受项原样保留在根包，不做任何挪动。

## 上游证据配置

两个服务都是依赖注入式的：构造函数注入共享的运行证据服务，再由它统一提供发布审批预演的快照数据。被阻断执行上下文档案服务从预演快照里取出沙箱连接前置回执，上游回执校验清单预检服务则直接消费整份预演快照。这种依赖注入的形态与上一刀凭据解析器家族完全一致，因此本次复用了同一套范式。

迁移到子包后，原本与运行证据服务、发布审批预演响应处于同包、可以省略导入的引用，现在必须显式导入这两个公开类型。除此之外，预检清单的支撑类还引用了运行证据服务上的一个共享 schema 版本字符串常量，这个常量原先是包级可见的，迁出后跨包不可达，于是本版本把这个不可变字符串常量改为公开。这一步是行为中立的可见性放宽，不改变任何取值。测试侧则继续复用上一刀已经公开的共享测试夹具来构造被注入的运行证据服务。

## 服务层核心流程

被阻断执行上下文档案服务的处理流程是：先取出预演快照与沙箱连接前置回执，再依次构造来源回执、上下文字段与归一化规则、前置证据、边界快照、执行护栏、告警回声、下游接收闸门，随后汇总出校验闸门与交接说明，最后交由渲染器拼出段落文本并由支撑类组装成完整响应。整个过程是只读的，没有任何写入或外部连接动作。

上游回执校验清单预检服务的处理流程是：取出预演快照后，依次构造来源回执、拆分模块清单、证据引用、预检字段、边界护栏、代码健康闸门，再汇总校验闸门与交接说明，最后同样经由渲染器与支撑类组装成响应。两个服务的端点字符串都由家族路由常量类的基础路径拼接各自的后缀得到，迁移后这个拼接逻辑保持不变，端点取值逐字节一致。

## Java 证据检查

Java 侧的证据检查集中在编译、可见性与静态分析三个层面。迁移过程中先做了一次仅编译，编译器精确地报出了缺失的导入：运行证据服务类型与发布审批预演响应类型分别被多个迁出文件按同包方式引用，迁出后需要显式导入；补齐导入后再次编译，又暴露出预检支撑类引用了一个包级可见的共享 schema 版本常量，于是把该常量公开。第三次编译干净通过，证明主代码的引用关系全部闭合。

随后做了一次仅测试编译，确认迁出的测试与改写后的根部控制器测试都能编译。最后通过完整验证流水线统一校验：单元测试全绿、各包覆盖率地板满足、静态分析零新增、代码风格零违规。家族里需要被静态分析接受的两个响应类型的暴露项，已经按新的全限定名平移，不会产生新的提示。

## mini-kv 证据检查

本家族的两条接口都不直接连接 mini-kv，而是以只读的方式陈述预演证据里关于 mini-kv 相关边界的状态。被阻断执行上下文档案强调的是“在阻断态下不会发起任何真实的外部连接，也不会读取凭据值”，其中也覆盖了与 mini-kv 适配器相关的占位说明；上游回执校验清单预检则把 mini-kv 相关的证据引用和拆分模块以清单形式呈现，供运维人员核对。

因此本次迁移对 mini-kv 没有任何运行时影响：既不改变连接行为，也不改变任何键值读写语义，更不会触发 mini-kv 的自动启动。所有与 mini-kv 有关的内容都停留在“只读陈述证据”的层面，迁移只是改变了承载这些陈述的类所在的包，不触及任何实际的网络或存储动作。

## 阻断与安全边界

本版本严格守住既有的安全边界。两条路由都标注了只读事务语义，不写库、不路由活跃分片、不读取凭据值、不解析原始端点地址、不发起真实的沙箱连接、不建立受管审计的网络连接。被阻断执行上下文档案的命名本身就强调“被阻断”，它的执行护栏逐项证明诸如凭据值读取、库表迁移语句、外部受管审计连接、真实连接尝试这些动作都没有发生且处于关闭态。

归档边界同样不可触碰：本次迁移不重命名也不移动任何归档根目录，从 `a/` 到 `f/`、形如 `e/<version>/` 的目录、各类证据 JSON、截图归档以及历史代码讲解目录都原地不动。这样 Node 侧对 Java 证据归档的引用不会失效。本版本不打开任何部署、回滚、自动启动或历史归档搬迁的口子。

## 测试覆盖

测试迁移遵循既定切分原则。两套子簇各自的目录级测试——来源、边界、不可变、拆分等纯包内测试，连同两个包级测试支撑类，一起迁入测试子包；迁入后的测试支撑类改为显式导入已公开的共享测试夹具来构造被注入的服务。而两条“路由加控制器”的组合测试则留在根包，因为它们需要断言家族后缀常量与根部全局聚合类里同名的包级常量逐字符相等，这一断言依赖根包内的可见性。

留在根包的两个组合测试不再依赖迁出的测试支撑类，而是各自内联一个私有构造方法，直接通过共享测试夹具来装配服务。为防止回退，本版本新增了一个专门的守护测试，逐一断言二十六个迁出文件确实位于新子包、且不再出现在根包，同时断言两个控制器与全局聚合类仍留在根包；并把根包直接文件数的治理阈值从一千二百六十九下调到一千二百四十三。

## 实际工作量说明

本节据实说明工作量，绝不夸大，也禁止硬凑字数。本次真实改动包括：用版本控制移动二十六个主代码文件并改写包声明；把家族路由常量类与其基础路径、两个后缀常量改为公开；为三个引用运行证据服务、十个引用发布审批预演响应的迁出文件补齐显式导入；把运行证据服务上的一个共享 schema 版本常量公开；为两个控制器与全局聚合类补齐子包导入；迁移九个测试文件并为两个测试支撑类补齐夹具导入；改写两个根部组合测试以内联构造服务；把十一条静态分析接受项平移到新的全限定名；下调治理阈值；新增守护测试、抽离说明文档、变更日志、进度行与本讲解。

工作量的真实难点不在文件数量，而在于依赖注入家族跨包后必须逐一闭合的可见性：扁平根包里大量同包省略导入的引用，迁出后会集中暴露，因此本版本采用“先仅编译、再仅测试编译、最后完整验证”的三段式排错，让编译器精确点名每一个缺失导入与不可达常量，再逐项修复，避免把问题留到耗时的完整验证阶段才发现。

## 一句话总结

本项目在 v1803 把沙箱连接这一依赖注入式证据家族的二十六个实现文件整体迁入更窄的维护子包，根包直接文件数从一千二百六十九降到一千二百四十三，两条只读路由、两个响应模型与全部只读语义逐字节不变，是迄今单版本最大的一次根包压力下降。
