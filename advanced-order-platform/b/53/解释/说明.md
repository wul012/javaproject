## 本版目标

v53 目标是让订单幂等从“服务层直接查 `OrderRepository`”推进到“通过 `IdempotencyStore` 抽象查找和保存”：

```text
POST /api/v1/orders
 -> 计算请求指纹
 -> IdempotencyStore.findByKey(...)
 -> 命中则按 key + fingerprint 重放或 409
 -> 未命中则走库存预占、订单保存、Outbox、历史流水
```

本版明确不做：

```text
不把 mini-kv 接入 POST /api/v1/orders
不改变订单权威存储
不改变库存、支付、Outbox 或失败事件 replay 事务
不让 Node 触发任何真实写操作
```

## 成熟度变化

v53 让订单幂等边界进入“可替换存储接口”的阶段，但仍保持生产安全边界：订单数据库继续是权威存储，mini-kv 只是后续短 TTL token 实验位。这样后续可以沿计划推进 mini-kv v62 的 TTL recovery evidence，再由 Node v161 组合成受控演练 runbook。

## 一句话总结

Java v53 把订单幂等存储抽象为 `IdempotencyStore`，并用 evidence、静态样本和测试明确证明当前仍走 JPA/DB，mini-kv 未接入交易主链路。
