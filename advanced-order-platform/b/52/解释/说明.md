## 本版目标

v52 目标是让订单创建具备可解释的幂等边界：

```text
同一个 Idempotency-Key + 相同请求
 -> 稳定重放已有订单
 -> 不二次预占库存
 -> 不二次写 Outbox

同一个 Idempotency-Key + 不同请求
 -> 稳定 409 拒绝
 -> 在库存预占和 Outbox 写入之前停止
```

本版明确不做：

```text
不接 mini-kv
不把 mini-kv 作为订单权威存储
不改变支付、退款、库存扣减、失败事件 replay 事务
不打开 UPSTREAM_ACTIONS_ENABLED
```

## 成熟度变化

v52 让订单创建幂等从“只按 key 返回旧订单”升级为“key + 请求指纹共同确认重放边界”。这解决了同一个 `Idempotency-Key` 被不同请求误复用时可能返回旧订单的问题。

这版仍保持 Java 数据库是订单权威存储，mini-kv 只是后续 TTL token candidate，不进入交易一致性主链路。

## 一句话总结

Java v52 把订单创建幂等边界补成可测试、可迁移、可被 Node 只读引用的生产硬化切片，为后续 Node v160 readiness review 提供 Java 侧证据。
